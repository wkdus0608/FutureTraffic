### 1.2 MLP(DQN의 신경망)

| 질문 | 답 |
|---|---|
| 모양 | 숫자 64개 입력 → 64칸 층 → 64칸 층 → 출력 4개(녹색 4개 각각을 켰을 때의 점수 예상). "64층"이 아니라 "64칸짜리 층이 2개"입니다. 가중치는 8,580개입니다 |
| 왜 MLP인가 | DQN이 보는 것이 숫자 64개 한 줄이기 때문입니다. 라이브러리(Stable-Baselines3)의 DQN 선택지는 숫자 한 줄용(MLP), 그림용(CNN), 여러 종류 입력 묶음용 세 가지뿐입니다. 그림이 아니니 MLP입니다 |
| 활성화 함수 | 있습니다. 층마다 ReLU(음수는 0, 양수는 그대로)입니다. 마지막 출력에는 없습니다. 점수 예상은 음수일 수도 있어서입니다 |
| 신경망이 두 개? | 맞습니다. 계속 배우는 **본 망**과, 정답 계산에만 쓰는 **목표망**입니다. 목표망은 5,000단계마다 본 망을 복사합니다. 정답을 내는 망이 덜 흔들려 학습이 안정됩니다 |
| Double DQN? | 아닙니다. Double DQN은 이름이 비슷한 다른 개선 방법이고 아직 쓰지 않았습니다. DQN은 지난 경험을 저장해 두고 다시 배우는 off-policy 방식입니다 |
| 다른 방법, 가장 좋은 것 | Double DQN, Dueling DQN, PPO 등이 있습니다. 무엇이 가장 좋은지는 미리 알 수 없어서, 환경을 확정한 뒤 검증 날짜로 비교하겠습니다 |
| 망을 키우면 느려지나 | 재 봤습니다. 64-64에서 512-512로 키워도 학습 시간은 66.5분에서 66.8분으로 거의 같습니다. 시간의 99% 이상이 SUMO의 교통 계산이기 때문입니다. GPU는 오히려 느렸습니다(68~70분). 그래서 망 크기는 시간이 아니라 성능으로 고르면 됩니다 |
| **MLP가 최적인가(오늘 진단)** | 학습 기록 5개로 확인했습니다. ① 은닉층 없는 선형보다 MLP가 확실히 낫습니다(검증 R² 0.917 → 0.938). ② 32-32부터 256-256-256까지 결과가 같아 64-64면 충분합니다. ③ 그런데 학습된 DQN은 Q값이 "100초(판단 20번) 앞까지의 점수"만 담고 있었습니다. 목표망을 10만 단계 동안 약 20번만 바꿔서입니다. 그래서 개선할 곳은 망 크기가 아니라 학습 설정(목표망 교체 간격)이고, 다음에 비교해 보겠습니다(`docs/MLP_판단_20261015.md`) |

## 2. 그동안 한 일

### 2.1 충돌 원인 3건 — 같은 조건으로 다시 돌려 모두 똑같이 재현

- **① 석천사거리 안**: 단순 제어가 신호 순서를 건너뛰었습니다(길주로 좌회전 → 석천로 좌회전, 실제 신호에는 없는 순서).
  - 황색 4초가 끝났을 때 12m 버스의 뒷부분이 아직 교차로 안에 있었는데, 맞은편 좌회전이 바로 녹색이 되어 겹쳤습니다.
  - 신호 규칙의 문제라 **고칠 수 있습니다.** DQN도 이 순서를 하루 약 85번 씁니다.
- **②·③ 교차로 밖**: 지도 모양 문제(급하게 꺾이는 분기점, 짧은 합류점)입니다. 고칠 수 없어 따로 세어 보고합니다.

### 2.2 신호가 바뀌는 순간 33만 번 측정

- **통과 후 간격**: 앞 신호의 마지막 차가 빠져나간 뒤, 다음 신호의 첫 차가 그 자리에 오기까지 걸린 시간입니다. 0보다 작으면 두 차가 같은 자리에 있었던 것이고, 1초보다 작으면 아슬아슬한 경우입니다.
- 학습·검증 15일 × 정책 8개 × 도착 방식 2가지 = 162번 실행했습니다(시험 날짜는 쓰지 않음).
- 결과:
  - 실제 신호에 있는 "길주로 직진 → 길주로 좌회전"도 빠듯했습니다. 고정신호에서도 1초 미만이 80번 나왔습니다.
  - 가장 위험한 것은 DQN이 쓰는 "석천로 좌회전 → 길주로 좌회전"이었습니다.

### 2.3 전환 규칙(전적색)

- 전환마다 모든 방향 빨간불을 몇 초 둘지 정했습니다.
  - **1초 기준**: 전환 6개에 1~2초
  - **1.5초 기준**: 전환 9개에 1~3초
- AI Hub 신호 기록에는 전적색이 한 번도 없습니다. 실제 도로에 있는데 기록에서 빠진 것인지 알 수 없어서, 고정신호는 **"원자료 그대로"와 "전적색 보정"을 둘 다 보고합니다.**
  - 보정 방법: 끝나는 녹색의 마지막 2초를 빨간불로 바꿉니다.
  - 길주로 직진 녹색 69초 중 2초(3%)이고, 다음 녹색이 켜지는 시각은 실제 기록과 같습니다.

### 2.4 석천로 북쪽 도로 늘리기

- AI Hub 지도가 정지선 58m 위에서 끝나서 줄이 23대분밖에 안 보였습니다. 240m 늘려 298m(119대분)로 만들었습니다. 그 구간은 곧은 3차로로 가정했습니다.
- 평균 결과는 거의 그대로입니다(고정신호 +0.6초).
- 북쪽 맨 오른쪽 차로는 우회전·직진 공용이라, 이제 우회전 차가 직진 줄 뒤에 막히는 모습이 실제처럼 생깁니다(우회전 지연 13초 → 26초).
