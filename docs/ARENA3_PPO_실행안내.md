# ARENA3 PPO 실행 안내 (2026-10-30)

교수님이 제안한 Stable-Baselines3 계열의 PPO를 지금까지와 같은 조건에서 시험한다. 배경은 220·221절, 설정은 `config/arena3_ppo_v1.json`.

## 무엇을 겨루나

| 이름 | 출발점 | 묻는 것 | 짝 비교 상대 |
|---|---|---|---|
| P1 | M4(G1과 같은 출발, 처음 탐험도 G1과 같게) | 같은 조건에서 PPO가 DQN보다 나은가 | G1 |
| P2 | 같은 난수의 S2A_pre | PPO 미세조정이 사전학습 위에 이득을 더하는가 | S2A_pre(그리고 S2A·S2B) |

- 같은 것: 관측 119칸, 6모드 행동(갈림길에서만 고름), 에피소드가 끝난 뒤 정확히 정산한 지연 보상, G1과 같은 학습 상황, 같은 심판 84상황.
- 다른 것: 학습 규칙만 PPO. SB3 PPO 기본값(클립 0.2, GAE λ 0.95, 에포크 10, 미니배치 64, 학습률 3e-4, 이득 정규화, 엔트로피 0, 행위자·평가자 64-64)을 따른다.
- SB3 라이브러리를 직접 쓰지 않는 이유: SB3 환경은 5초마다 보상을 바로 돌려줘야 하는데, 우리 보상은 에피소드가 끝난 뒤 차량 기록으로 정산한다. 그대로 쓰면 보상을 근사로 바꿔야 해 G1·S2와 비교가 깨진다.
- 선택 사이 시간이 달라서 할인은 0.99^(지난 5초 단계 수), GAE 계수는 (0.99·0.95)^(단계 수)로 잇는다.
- 처음 두 번의 갱신은 평가자(가치망)만 맞춘다. 2단계 DQN 미세조정에서 의심된 '가치 값이 0에서 시작해 신경망이 흔들리는' 문제를 피하려는 것이다.
- 예산: 난수마다 에피소드 448판(G1 수준), 8판마다 한 번 갱신(56번). 시간이 아니라 판 수로 센다.

## 판정 (결과를 보기 전에 정함)

- 주 판정: 1단계와 같은 M4 대비 판정(날짜 평균 ≥ 0.3초, t95 하한 > 0, 양수 날짜 ≥ 5, 좌회전 +5초 이내, 300초 초과 ≤ M4, 정책 고유 충돌 0, 품질 오류 0).
- P1 − G1의 평균 > 0, t95 하한 > 0 → "같은 출발·같은 학습 상황에서 PPO가 DQN보다 짧다".
- P2 − S2A_pre의 평균 > 0, t95 하한 > 0 → "PPO 미세조정이 사전학습 위에 이득을 더했다". 구간이 0을 지나면 "구분 못 함".
- C1·C2 확인: P1·P2 중 주 판정을 통과한 것 가운데 날짜 평균이 큰 하나만 한 번 잰다(기준선은 2단계 확인 기준선 재사용).

## 준비 (맥에서 이미 함)

- 묶음 `FutureTraffic_ARENA3_PPO.zip`과 노트북 세 개(`ARENA3_PPO_P1.ipynb`, `ARENA3_PPO_P2.ipynb`, `ARENA3_PPO_judge.ipynb`)를 Drive `FutureTraffic/`에 올렸다.
- 결과는 `arena3/ppo_P1/`, `arena3/ppo_P2/`, `arena3/ppo_judge/`에 따로 쌓인다. 런타임마다 다른 폴더라 같은 이름 폴더가 둘 생기지 않는다.

## 순서

1. **P1과 P2를 동시에** 새 런타임 두 개에서 연다. 런타임 유형은 **CPU + 높은 RAM**(CPU 8개). 첫 칸이 CPU 수를 확인하고, 8개가 아니면 멈춘다. **모두 실행**.
   - 실행 전 점검(진짜 SUMO 4판, 약 10분) → 학습 난수 3개 동시(약 10시간) → 평가 252판(약 1.5시간) → 참고 판정.
2. **둘 다 끝나면** `ARENA3_PPO_judge`를 새 런타임에서 연다. **모두 실행**.
   - 개발 판정 → 통과한 PPO가 있으면 C1·C2 확인(약 1.5시간). 없으면 바로 끝난다.
   - P2만 돌렸다면 첫 칸의 `RUN = ("P1", "P2")`를 `("P2",)`로 바꾼다.

## 끊겼을 때

- 처음 네 칸(Drive·묶음·패키지·시험)을 돌린 뒤 멈춘 칸부터 다시 실행한다(또는 **모두 실행**).
  - 점검은 끝났으면 건너뛴다. 학습은 체크포인트에서 이어진다(8판마다 저장). 평가는 끝난 판을 건너뛴다.
- 오류가 나면 마지막 칸 출력과 `arena3/ppo_P1/logs`(또는 `ppo_P2/logs`)의 로그를 보낸다.

## 읽는 법

- 반복 사용 날짜의 SUMO 개발 비교다. C1·C2는 같은 7일의 새 도착 배치이며 새 날짜·실제 도로 일반화는 아니다.
- 기대치(사전 예상, 근거 약함): PPO도 SUMO를 한 번 지나가며 배우므로, 같은 상황에서 두 신호를 비교한 자료가 없다는 한계는 그대로다. P2는 사전학습 성능을 지키는 정도, P1은 G1 근처일 가능성이 높다고 본다. 이 예상은 판정 기준이 아니다.
