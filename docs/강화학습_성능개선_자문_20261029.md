**2. 현재 학습 방식에 대한 정확한 이해**

- S2A는 후보의 M4 대비 상대 이득을 회귀하고, S2B는 좋은 후보의 선택 분포를 모방한다. S2B도 별도 PPO actor가 아니라 같은 Q 출력의 차이에 분류 손실을 적용한다.
- 이후 SUMO에서 실제 제어한 경험으로 Double DQN·dueling 구조·3개 선택 지점 n-step·시간 간격을 고려한 SMDP 학습을 수행한다.
- 학습 중에도 고정된 교사 자료를 사용하며 보조 손실 가중치 0.2를 끝까지 유지한다.
- 행동은 6개 계획기 모드가 제안한 첫 녹색 중 고르는 것이다. 같은 녹색을 제안하는 중복 모드는 제거한다. 계획기 의견이 갈릴 때만 RL이 선택한다. 모든 합법 녹색을 항상 자유롭게 고르는 구조는 아니다.
- 보상은 이미 실제 timeLoss와 departDelay를 정산한다. 과거의 정지 차량 수 보상 문제를 현재의 미해결 사항처럼 다시 제안하면 안 된다.

근거: `src/arena3_stage2_data.py:241`, `src/arena3_stage2_train.py:159`, `src/arena3_g1.py:82`, `src/arena3_g1.py:118`, `src/arena3_common.py:379`, `src/explore_weight_episode.py:61`.

현재 코드는 SB3 기본 DQN보다 여러 장치가 추가된 자체 구현이다. 기본 SB3 DQN으로 바꾸는 것이 곧 알고리즘 강화는 아니다. [SB3 DQN 공식 문서](https://stable-baselines3.readthedocs.io/en/master/modules/dqn.html)는 Double·dueling·prioritized replay가 포함되지 않은 구현임을 명시한다.

**3. 결과가 나오면 먼저 볼 비교**

| 관측 결과 | 우선 해석 | 다음 조치 |
|---|---|---|
| 사전학습만으로 M4보다 좋은데 RL 후 악화 | 온라인 갱신이 좋은 정책을 훼손할 가능성 | 가치 보정, 초기 탐험, 교사 손실과 TD의 균형을 비교 |
| 사전학습부터 연속 제어가 미흡 | 단일 지점의 라벨과 연속 제어 간 차이 또는 학습·관측 한계 | 어떤 상태에서 잘못 바꾸는지 확인하고 같은 환경 PPO 비교 |
| RL 후 좋아졌지만 개선 폭이 부족 | RL 기여는 있으나 충분하지 않음 | 선택 경험 수·학습 곡선·seed별 결과를 보고 PPO와 비교 |
| 전체 지연은 개선되나 좌회전·장기 대기 실패 | 평균 지연 목표만으로 제약을 충족하지 못함 | 해당 방향의 지연 또는 장기 대기 비용을 학습 신호에 반영하는 별도 비교 |
| 최종 RL이 기존 판정과 C1/C2를 통과 | 현 접근의 성과가 확인됨 | 사전학습 대비 RL 기여를 별도로 보고하고 12교차로 확장은 다음 단계로 수행 |

최종 RL이 M4를 넘었다는 것과 RL이 사전학습보다 더 개선했다는 것은 서로 다른 주장이다. 둘 다 확인해야 결과를 정확히 설명할 수 있다. 사전학습 모델의 성적만을 강화학습 성공으로 채택하지 않는다.

**4. 현재 코드에서 우선 검증할 가설**

확정적인 성능 저하 버그를 찾은 것은 아니다. 가장 눈여겨볼 구조는 교사 목표와 실제 RL 목표의 차이다.

교사는 “지금 이 행동을 한 뒤 M4를 계속 쓰면 300초 대리 비용이 얼마나 줄어드는가”를 가르친다. 온라인 TD는 “지금 이 행동을 한 뒤 현재 학습 정책을 계속 쓰면 실제 할인 누적 지연이 얼마인가”를 학습한다. 두 목표는 같은 값이 아니다. 그런데 같은 Q 출력에 교사 손실을 계속 더한다(`arena3_stage2_train.py:169–184`).

이 방식은 배운 판단을 유지할 수도 있고, 현재 정책에 맞게 달라져야 하는 판단을 붙잡을 수도 있다. 교사 손실을 무조건 없애거나 영구 유지하라고 단정할 근거는 없다. G1이 실패했다는 사실만으로 “사전학습 후 교사 손실을 줄이면 반드시 실패한다”는 결론도 나오지 않는다. G1은 B′ 사전학습에서 출발한 실험이 아니기 때문이다.

또한 사전학습 손실은 Q(a)−Q(M4)를 사용해 공통 value 값을 상쇄한다. 0으로 초기화한 value head는 사전학습만으로 실제 누적 지연에 맞춰지지 않는다(`arena3_g1.py:82–95`, `arena3_stage2_data.py:244–246`). RL을 시작할 때 행동 순위는 배웠지만 절대 가치 규모를 새로 맞춰야 한다. 이것도 오류라기보다 사전학습에서 RL로 넘어가는 위험 지점이다.

현재 초기 무작위 탐험 확률은 0.5, 최종 0.1, 학습률 0.001, 새 선택 전이당 갱신은 8회다(`config/arena3_v1.json:198–208`). 사전학습이 좋은 경우 초기 탐험과 갱신을 더 완만하게 하는 것이 후보가 된다. 예를 들어 학습률 0.0003 또는 초기 탐험 0.1~0.2는 작은 비교의 시작값일 수 있지만, 이 프로젝트에서 검증된 최적값은 아니다. 한 번에 모두 바꾸지 않는다.

추가할 진단 기록은 전체 손실뿐 아니라 TD 손실·교사 손실·가중 후 기여·Q와 TD 목표의 크기·실제 선택 횟수·M4와 다른 녹색을 실행한 비율·좌회전 지연이다. 현재 기록은 두 손실의 합을 주로 남겨 원인 분리가 어렵다. 마지막 모델만 보지 말고 학습 날짜 안에서 별도로 고정한 검증 조건으로 중간 모델도 비교한다.

**5. 새로운 알고리즘의 우선순위**

| 후보 | 우선순위와 이유 |
|---|---|
| MaskablePPO | 첫 후보. 상태마다 가능한 행동이 달라지는 현재 이산 선택에 맞고, 행동 확률과 가치 평가의 역할을 나눌 수 있음 |
| QR-DQN | 다음 후보. 반환값 분포를 학습하는 가치 기반 대안. 현재 마스크·시간 할인·교사 학습의 이식은 별도 작업 |
| A2C | 이산 행동을 지원하는 비교 후보. 제한된 예산에서 PPO보다 먼저 넓게 시험할 필요는 낮다고 판단 |
| RecurrentPPO | 명시적 이력 부족이 실제 병목일 때 검토. 공식 MaskablePPO와 recurrent 정책이 바로 결합되지는 않음 |
| TD3·SAC | SB3 구현은 연속 행동용. 현재 모드 선택의 직접 대체 후보는 아님. 녹색시간 같은 연속 제어를 연구할 때 검토 |

지원 범위의 근거: [SB3 알고리즘 표](https://stable-baselines3.readthedocs.io/en/master/guide/algos.html), [MaskablePPO](https://sb3-contrib.readthedocs.io/en/master/modules/ppo_mask.html), [QR-DQN](https://sb3-contrib.readthedocs.io/en/master/modules/qrdqn.html). 우선순위는 현재 프로젝트 구조에 대한 판단이며 성능 순위가 아니다.

PPO는 좋은 결과를 낸 행동의 확률을 높이되 정책이 한꺼번에 과도하게 바뀌지 않도록 갱신을 제한한다. 경우의 수를 탐색하는 범위를 줄이는 알고리즘이라는 설명은 부정확하다. [PPO 원논문](https://arxiv.org/abs/1707.06347).

권장 구성은 **B′ 자료 → PPO 정책망 사전학습 → 실제 SUMO 경험으로 가치망 학습·PPO 갱신**이다. 기존 DQN 모델 파일을 PPO에 그대로 읽는 방식이 아니라 교사 자료를 재사용한다. B′의 상대 이득을 PPO 가치망의 절대 가치 정답으로 직접 넣지 않는다. 필요하면 정책을 고정한 짧은 rollout으로 가치망을 준비한 뒤 두 망을 함께 학습하는 방식을 비교한다. 정책 변화가 큰 초기에 낮은 학습률이나 KL 기준을 쓰는 것도 후보이며, PPO 자체가 성능 하락을 완전히 막는 것은 아니다.

기본 비교는 기존 S2A/S2B 결과, 사전학습 없는 MaskablePPO, B′ 사전학습 MaskablePPO로 좁힌다. 교사 보조 손실을 PPO 중에도 쓰는 것은 사용자 정의 추가 기능이다. 교사 유지/감소 비교는 결과에서 필요성이 드러날 때 추가하며, 표준 라이브러리에 자동 포함된 기능처럼 설명하지 않는다. PPO는 새 정책으로 모은 경험을 쓰므로 SUMO 표본 효율이 DQN보다 좋다고 보장하지 않는다.

**6. PPO로 바꿀 때 비교 조건을 유지하는 방법**

- 처음에는 관측 119개·6모드 후보·중복 제거·보행 및 최소 녹색 제약·실제 지연 보상을 그대로 둔다. 알고리즘과 행동 범위를 동시에 바꾸지 않는다.
- 현재는 선택 사이 실제 시간에 따라 γ를 적용한다. 선택 지점 한 번을 무조건 PPO 한 step으로 만들면 시간 기준이 달라진다. 표준 PPO를 최대한 유지하려면 매 5초를 한 step으로 감싸고, 선택권이 없는 구간에서는 유효 행동이 하나뿐인 마스크를 쓴다. 그 구간은 정책을 개선하는 정보가 적으므로 실제 선택 횟수와 actor 학습 비중을 점검한다. 선택 지점만 모으는 방식을 유지하려면 기간별 할인과 GAE/rollout buffer 처리를 따로 구현해야 한다.
- 학습과 평가에 같은 행동 마스크를 적용한다. 병렬 환경에는 환경 내부 `action_masks()`가 필요하고, 공식 전용 평가 도구를 사용하거나 기존 심판에 동등하게 마스크를 전달해야 한다. [MaskablePPO 공식 지침](https://sb3-contrib.readthedocs.io/en/master/modules/ppo_mask.html).
- 같은 숫자의 step만으로 예산을 맞추지 않는다. SUMO 제어시간·실제 선택 수·경사 갱신 수·계산시간을 함께 기록한다. 고정 5초 step과 압축된 선택 지점 step의 숫자는 다르다.
- 기존 심판의 +0.3초·날짜별 개선·좌회전·장기 대기·충돌 기준을 보존한다. 모델 3개 평균뿐 아니라 각 seed의 결과도 본다. C1/C2는 후보를 정한 뒤 한 번 확인하고, 반복 튜닝에 쓰지 않는다. 새 모델을 계속 비교할 경우 검증과 확인 구분을 다시 명확히 한다.

**7. PPO에서도 미흡할 때의 다음 가설**

관측은 이미 신호 시간, 밀도·정지비율, 이동별 큐·대기, 보행 대기, 진입 대기, 계획 비용 차이, 남은 제어시간을 포함한다. 단순히 관측 개수를 늘리는 접근을 반복하지 않는다. 최근 이동별 유입률과 변화량, 상류 차량의 도착예정시간 분포는 명시적으로 포함되지 않으므로, 잘못된 선택이 유입 변화와 연결될 때 해당 정보를 추가하는 비교가 타당하다. 불확실성의 원인이 이력인지 확인하기 전에 LSTM부터 도입할 필요는 없다.

행동 범위도 별도 가설이다. 현재는 어느 계획기도 제안하지 않는 녹색을 RL이 고를 수 없다. 같은 6모드에서 알고리즘 비교를 마친 다음, 안전·보행·최소 녹색 제약을 유지하면서 모든 합법 녹색을 직접 고르는 MaskablePPO를 별도 분기로 고려할 수 있다. 탐색 범위가 커져 오히려 학습이 어려워질 수도 있다. B′가 현재 후보 범위 안에서 개선했으므로, 행동 확대가 반드시 먼저 필요한 것은 아니다.

학생이 방문한 상태를 다시 라벨링하는 방식은 PI1에서 이미 일부 시험했고 연속 제어가 악화됐다(`PROJECT_PROGRESS.md:4289–4359`). 다시 시도한다면 현재는 M4보다 개선이 확인된 B′ 교사가 있다는 차이와 독립 표본 미래에서 라벨 신뢰도를 확인하는 절차가 있어야 한다. 모든 상태를 다시 모으기보다 손실이 큰 상태에 한정하고 실제 온라인 RL을 계속한다.

마지막으로 실제 비용 정산이 맞아도, 할인된 학습 목표와 비할인 전체 지연·방향별 제약은 완전히 같지는 않다. 할인율 조정이나 방향별 비용 추가는 실패한 지표에 맞춘 후속 실험으로 둔다. 지금의 보상을 막연히 queue나 pressure 보상으로 교체하는 것을 첫 처방으로 삼지 않는다.

권고 순서는 **현재 S2A/S2B 완료 → 사전학습/최종 RL 비교 → 필요한 경우 전이 과정의 작은 수정 → 동일 조건의 B′ 사전학습 MaskablePPO → 근거에 따른 관측 또는 행동 범위 확대**다. 지금의 B′ 성과는 다음 RL 시도를 뒷받침하지만, 특정 알고리즘의 성공 확률이나 개선 폭을 보장하지 않는다. 모든 성과 주장은 반복 사용 날짜의 SUMO 개발 비교 범위로 제한한다.
