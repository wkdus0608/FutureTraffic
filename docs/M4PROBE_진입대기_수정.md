# M4 진입 대기 복원 수정

이전 진단은 20220812 07:30 난수 43의 저장 시점에 진입 대기 차량 `0745_p156` 한 대가 복원 직후 SUMO 대기 목록에 나타나지 않아 실패했다. 당시 원본과 복원본은 신호 후보가 같았고 5초 뒤 차량 상태도 일치했지만, 저장 직후 관측 한 칸이 달랐다. 5초 뒤 같다는 이유만으로 불일치를 무시하지 않는다.

새 실행은 저장 당시 진입 대기 차량 ID·경로·진입 대기 값을 함께 저장한다. SUMO가 복원 직후 목록에서 누락한 차량은 복원된 SUMO에서 해당 ID의 경로와 대기 값이 원본과 같은지 **먼저 확인한 경우에만**, 저장한 그 순간의 대기 목록 조회에 복원한다. 차량을 새로 만들어 넣지 않고, 시뮬레이션이 한 번 진행되면 원래 SUMO의 대기 목록을 그대로 사용한다. 조회가 불가능하거나 값이 다르면 실패하고 이유를 남긴다.

복원한 직후의 신호·차량·대기 상태와 110칸 관측을 비교하고, 원본 M4와 실제 미래를 이용한 복원 M4를 **300초 동안 매 5초** 비교한다. 각 시점의 관측, 허용 현시, 모드별 행동과 실행 후 모든 차량의 차로·위치·속도·대기 목록·신호가 일치하지 않으면 해당 상태를 채택하지 않는다. 실제 미래는 이 복원 정확도 검사에만 사용한다. 표본 미래를 주입한 경우에도 판단 직전 관측 110칸이 원본 상태와 동일한지 검사한다.

기존 상태는 원본대로 `explore_m4probe_v1`에 보존한다. 새 복원 방법과 강화된 300초 검증을 모든 상황에 똑같이 적용하기 위해 결과는 별도 `explore_m4probe_pending_v1`에 저장하고 상태를 다시 수집한다. 날짜·시간대·난수·후보·표본 미래·판정은 원래 사전 계획을 유지한다. 사용자 요청에 따라 작업시간·계산량 상한은 없다. 300초는 비교하는 시뮬레이션 구간이며 컴퓨터 실행시간 제한이 아니다.

2. CPU 런타임을 선택하고 **런타임 → 모두 실행**을 누른다.
3. 이전에 실패한 난수 43 상황을 먼저 300초 연속 검증한다. 통과하면 나머지 상황을 자동으로 이어간다.
4. 다시 오류가 나면 해당 상태를 버리거나 자동으로 넘어가지 않고 Drive `explore_m4probe_pending_v1/restore_diagnostics/`에 이유를 저장한다. 오류가 났다고 알려 주면 확인한다. 완료되면 알려 준다.
