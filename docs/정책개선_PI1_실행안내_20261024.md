# 한 차례 정책 개선(PI1) 실행 안내

> **2026-10-25 완료 기록.** 실행 전 기준은 [진행 기록](../PROJECT_PROGRESS.md) 156절, 준비는 157절, 결과는 158절이다. PI1은 정책 개선 미확인으로 완료했다. 아래 명령·순서는 재현용 이력이며 새 실행을 권하는 안내가 아니다. 결과를 보존하고 42번 칸을 다시 실행하지 않는다.

## 완료 결과

**10-25 결과: 정책 개선 미확인.** 수요 이력 29칸은 사전 기준을 통과하지 못해 96칸 부모(B)를 유지했다. 부모가 방문한 학습 상태 48개에서 후보를 비교했고, 독립 확인 미래의 이득 합 +2,241대·초·3묶음 중 2개 양수·22개 선택 변경으로 학생 한 번 학습 기준을 통과했다. 그러나 실제 연속 제어에서는 그 이득을 유지하지 못했다.

| 정책 | 평균 차량 지연 | 부모보다 줄인 지연 | P0보다 줄인 지연 |
|---|---:|---:|---:|
| P0 | 39.30초 | — | — |
| 부모 B | 39.49초 | 기준 | −0.19초 |
| PI1 학생 | 39.89초 | **−0.40초** | **−0.59초** |

판정 뒤 추가 학습 없이 고정 가중치로 검사한 결과, 새 학생은 학습 장면 48개 중 탐색 선택과 47개가 같았고 선택용 미래의 예상 이득 99.86%를 회수했다. 배운 장면을 맞히는 것은 확인했으나 실제 연속 제어 개선은 아니며, 실패 원인을 일반화 하나로 확정하지 않는다.

부모 대비 줄인 지연의 4묶음 95% 구간은 [−1.37, +0.57]초, 개선 묶음은 1/4다. 개선을 확인하지 못했으며 일반적인 악화가 확정된 것은 아니다. 동쪽 좌회전은 117.73 → 112.72초로 줄었지만 남쪽은 98.59 → 105.04초로 늘어, 부모 대비 5초 이내 조건도 통과하지 못했다. 네 수요 조건의 seed 반복을 다시 쓴 개발 평가이며 새 날짜 최종 시험이 아니다.

누적 비용은 **33,070.86 CPU초 / 상한 36,000초**다. 요약의 평가 48개에서 누락·미완료·규칙 개입·충돌·300초 초과는 모두 0이다. 원시 평가 48개가 요약과 같고 P0·부모의 기존 32개 결과도 재현됐다. 코드 지문·모델 10개 해시·실험 지문·CPU 장부 대조를 통과했다. 결과는 `results/explore/policy_iter_20261025/`이며 근거는 진행 기록 156~158절이다. **자동 추가 수집·두 번째 라운드는 시작하지 않는다.**

## 당시 실험 목적

학생이 직접 운영한 상황에서 후보 신호를 시험하고, 후보 이후에도 현재 학생이 운영한 결과를 다음 학생이 배운다. 기존 탐색의 ‘첫 후보 이후 P0 운영’에서 ‘첫 후보 이후 고정 부모 운영’으로 학습 비용을 바꾸는 한 차례 근사 정책 개선이다. 성공이나 무손해를 보장하지 않는다.

출발점은 COMBO B(96칸·비용 회귀·32-32·5모델 평균·문턱 0)다. 개발 평가에서 P0에 가장 가까웠기 때문에 후속 후보로 골랐고, 다른 학생보다 통계적으로 우수하다고 확인된 것은 아니다. P0 종단 비용을 학습하는 새 구조로의 전환과 자동 두 번째 라운드는 이번 범위에 없다.

## 당시 실행 순서(완료, 재실행 지시 아님)

새 `FutureTraffic_focused.zip`을 Drive `MyDrive/FutureTraffic/`에 둔 뒤, 갱신한 노트북을 연다.

1. **1~3번 칸**으로 새 묶음을 풀고 설치한다.
2. **42번 칸만** 실행한다. 완료된 **37~41번 칸은 다시 실행하지 않는다. ‘모두 실행’도 쓰지 않는다.**
3. 종료 후 Drive `explore_policy_iter/`의 요약과 중단 사유를 확인한다. 명령이 오류 없이 끝났어도 탐색 기준 미통과로 학습·평가를 하지 않았을 수 있다.

## 입력 자료와 보호 장치

입력은 완료된 Drive 자료다. 예전 실험을 재실행해 새로 만들지 않는다.

- `explore_online/runs/`: 기존 탐색 실행 6개.
- `explore_collect/runs/`: 새 날짜 탐색 실행 3개.
- `explore_combo/features/`: 재생 9개의 관측 중 탐색 시점 314개.
- `explore_combo/students/b/`: 고정 출발 학생의 `policy.json`과 `seed0.pt`~`seed4.pt`.
- `explore_combo/eval/`·`summary.json`: 완료된 80개 평가와 요약.

42번 칸은 잠근 `pet1`·북쪽 연장 240m 환경, 기존 모듈의 코드 지문, B의 설정·가중치, 입력 수를 먼저 검사한다. 새 PI1 코드는 이번 묶음의 파일 검사값과 같아야 한다. 실제 SUMO 후속 정책 검사는 본 후보 탐색 앞에서 실행한다. 맥에서 실제 검사를 하지 못했다면 통과한 것으로 간주하지 않는다.

준비 검사는 172개가 통과했다. 맥에서는 96칸 B로 학습 날짜 한 에피소드를 제어하고 상태 2개를 복원했다. 8개 후보·미래 조합에서 부모 후속 재실행과 기존 P0 비용 셈 대조가 일치했고 실제 미래 유출·규칙 개입은 없었다. 이는 장치 검사이며 PI1의 성능 판정에 사용하지 않는다. 125칸이 채택될 경우를 포함해 Colab은 그곳에서 검사부터 다시 한다.

실제 미래 출발 차량은 롤아웃 실행에서 제거한다. 부모가 수요 이력 29칸을 쓰게 됐다면 탐색 시작 이후 이력에도 실제 미래를 넣지 않고 표본 미래만 반영한다. 평가 날짜 08-11·08-23의 상태를 새 학습에 넣지 않는다.

## 고정한 실험 조건

- **수요 이력:** 최근 900초 예정 출발의 이동 14개+그 밖 1개, 차종 13개+그 밖 1개, 합 29칸. 각 값은 `min(1, log1p(대수)/log1p(1000))`. 실제 감지기 유입이나 상승·하락 추세가 아니다.
- **이력 채택:** 묶음 제외 총 이득이 0보다 크고 기존 96칸보다 크며, 6묶음 중 4개 이상에서 기존보다 좋을 때만 125칸을 쓴다. 아니면 B 96칸 그대로다. 진단 미통과가 이후 정책 개선을 중단시키지는 않는다.
- **학생 상태:** 08-12 18:00·08-19 13:00·09-26 18:00, seed 42. 각 묶음에서 시간순으로 고르게 최대 16개. 기록을 재생해 마지막 저장 대상까지 선택 시각·허용 후보·P0·부모 선택·관측이 같아야 한다.
- **탐색:** 600초, 끝 정체×75초. 선택 미래 8개(seed 3001~3008), 독립 확인 미래 8개(seed 4001~4008). 확인은 선택 후보와 부모 행동을 비교하며 학습 정답에 섞지 않는다.
- **후속 운영:** 기존 좌회전 정체 조건 안은 고정 부모, 밖은 P0. 원래 제어 종료 이후는 P0다. 탐색 중 부모 가중치는 바꾸지 않는다.
- **학습:** 새 부모 후속 상대 비용만 정답으로 쓴다. 기존 314개의 P0 후속 비용을 같은 정답으로 섞지 않는다. 기존 입력의 부모 출력 유지 벌점×0.1을 추가한다. Adam 0.0001, weight decay 0.001, 2,000회, 32-32와 5모델 평균·문턱 0을 유지한다.
- **계산 상한:** 전체 36,000 CPU초. 최대 후보 탐색 3,840회이며 소규모 검사·수집·평가도 같은 실험 예산에 포함한다. 병렬 수는 CPU 수와 4 중 작은 값이다. 4개를 계속 쓰는 36,000 CPU초는 약 2.5시간의 계산량에 해당하지만, 벽시계 완료 시간의 보장은 아니다. 상한 때문에 미완료라면 미완료로 적고 자동 확대하지 않는다.

CPU 예산은 완료 작업의 Python·종료한 SUMO CPU 합을 기록하고 새 배치를 제출하기 전에 여유를 검사하는 운영 상한이다. 배치 완료 직후에도 검사하며 초과를 감지하면 새 작업을 시작하지 않는다. 운영체제가 36,000초에서 실행 중인 작업을 즉시 강제 종료하는 방식은 아니므로 마지막 실행 묶음의 초과분이 생길 수 있다. 같은 코드로 재개할 때 완료 작업은 CPU를 중복 합산하지 않는다.

## 최종 결과를 읽는 법

개발 평가는 기존 제외 조건 08-11·08-23 × 13:00·18:00 × seed 42~45다. 네 수요 묶음 평균과 자유도 3의 95% 구간을 주 요약으로 쓴다. 16개는 독립된 16개 날짜가 아니다. 같은 평가를 이미 여러 번 썼으므로 새 시험 자료의 확정 성과로 부르지 않는다.

- **부모 대비:** 평균 0.5초 이상 개선, 묶음 구간 아래 끝>0, 4묶음 중 3개 이상 개선, 주요 좌회전 둘의 평균 악화 각각 5초 이내, 300초 초과 증가 없음이면 ‘한 차례 정책 개선 단서(개발 평가)’다.
- **P0 대비:** 같은 방향·구간·좌회전 조건에 평균 1.3초 이상 개선하면 ‘P0 초과 채택 기준 통과(개발 평가)’다. 부모보다 좋아져도 P0를 넘었다고 하지 않는다.
- 실행 유효성은 빠진 차·미완료·규칙 개입·중앙 충돌 0, 동일 차량 코호트와 P0 재현으로 확인한다. 실행 확인과 성능 판정은 별도다.

결과는 Drive `explore_policy_iter/`에 남긴다. 학습·평가를 하지 않은 경우 그 사유도 결과다. 기존 공식 DQN 성과와 COMBO 결과는 보존한다.

## 보존한 실행 명령(재실행 지시 아님)

완료한 Colab 42번 칸은 경로·환경·입력·가중치를 검사한 뒤 아래 명령을 실행했다. 재현 이력으로 보존하며 현재 새 본실험을 시작하지 않는다.

```bash
python src/explore_policy_iter.py run \
  --old /content/drive/MyDrive/FutureTraffic/explore_online/runs \
  --new /content/drive/MyDrive/FutureTraffic/explore_collect/runs \
  --combo /content/drive/MyDrive/FutureTraffic/explore_combo \
  --out /content/drive/MyDrive/FutureTraffic/explore_policy_iter \
  --work /content/policy_iter --workers 4 --cpu-budget-s 36000
```

CPU가 4개보다 적으면 42번 칸이 병렬 수를 자동으로 줄인다. 실행 전 계획의 원문·타이브레이크·정정 이력은 [진행 기록](../PROJECT_PROGRESS.md) 156절을 따른다.
