# WEIGHT1: P0 가중치를 선택하는 강화학습

2026-10-25. 사용자 확정 계획의 구현 안내다. 성능 개선 완료를 뜻하지 않는다. 기존 P0·환경·공식 결과는 보존한다.

P0는 120초 계획을 계속 계산한다. RL은 매 5초 기본값, 동쪽 좌회전 1.5배, 남쪽 좌회전 1.5배, 두 곳 1.5배, 두 곳 2배 중 하나를 고른다. 이동별 대기 비용과 종단 비용에 같은 양수 가중치를 적용한다. 기본 모드는 기존 계획 함수를 직접 호출한다. 전환·최소 녹색·보행·165초 규칙은 바꾸지 않는다. 165초 규칙은 현재 실행의 허용 행동에 적용되며, P0의 미래 줄 모형에 추가한 것은 아니다.

## 실행

프로젝트 가상환경에서 다음 명령으로 전체 경로를 시작한다. 초기 확인 6시간, 전체 48시간은 동시에 실행한 작업도 합산한다. 각 단계가 미통과하면 다음 단계는 실행하지 않는다.

```sh
.venv/bin/python src/explore_weight.py run --out results/explore/weight_v1 --work /tmp/weight_v1 --workers 2
```

Colab에서는 `notebooks/WEIGHT1_Colab.ipynb`를 사용한다. 전용 묶음은 `.venv/bin/python src/explore_weight_package.py`로 만들며 결과는 `results/colab/FutureTraffic_WEIGHT1.zip`이다. 기존 Colab 노트북과 zip은 덮어쓰지 않는다. ZIP과 새 노트북을 Drive `MyDrive/FutureTraffic`에 올린 뒤 새 노트북을 위에서부터 실행한다. `run`은 같은 명령으로 재개한다.

개별 명령은 `prepare`, `check`, `fixed`, `pilot`, `forecast`, `full`, `confirm`, `summary`다. `pilot`·`full`·`confirm`은 앞 단계 통과/완료 파일을 요구한다. `summary`는 시뮬레이션 없이 결과를 읽는다. 코드·설정·자료·충돌 예외 목록·프로그램 버전 지문이 다르면 기존 결과 재사용을 거부한다. 다른 버전은 새 폴더에 보존하되 같은 실험의 남은 예산을 초기화하는 용도로 사용하지 않는다.

## 학습과 비용 집계

- 관측은 고정 110칸이다. 모드 선택 마스크는 104~108번, 109번은 남은 제어시간이다. 기존 관측 끝의 현시 마스크와 구분한다.
- 신경망은 64–64 Double DQN, n-step10, gamma0.99다. 학습률0.001, 저장소10만, 배치64, 4단계마다 갱신, 목표망5,000단계 교체다. 탐험률은 첫20,000단계에 1.0→0.05, 이후0.05다.
- 같은 첫 현시를 내는 모드는 가장 작은 번호 하나로 묶는다. 강제 상태는 M0만 고른다. 저장소에는 모드 번호를 넣고 실제 목표 현시는 따로 기록한다. 황색 중의 목표 현시와 실제 표시 문자열은 구분한다.
- 30분 실제 신호 준비 운전→60분 제어→900초 원래 P0 후속 운전을 한다. 60분 동안 출발 예정인 같은 차량들이 평가 대상이다. 주변 차량과 이후 교통량은 계속 들어온다.
- 매5초 현재 차량 시간 손실을 기록하고, 종료 뒤 차량 기록의 마지막 timeLoss와 소수점 진입 대기를 정산한다. 비용 증가량의 음수/1000이 보상이다. SUMO가 보고하는 작은 음수timeLoss도 기존 평가와 같게 보존한다. 값을0으로 잘라 합계를 바꾸지 않는다.
- 후속900초 비용은 5초당gamma0.99로 할인해 마지막 제어 보상에 넣고 종료한다. 추가 bootstrap은 없다. 할인 전 비용 합과 최종 차량별timeLoss+departDelay 합은1e-6 이내로 일치해야 한다.
- 전체 에피소드 정산 뒤에만 n-step 전이를 저장하고 그 에피소드의 갱신을 수행한다. 모델·목표망·저장소·난수·시나리오 선택 상태를 에피소드 경계에 원자적으로 보존한다. 예비42회와 본139회 모델은 별도 불변 사본이다. 학습 도중 임의 모델을 골라 평가하지 않는다.

## 단계와 판정

1. 원래 P0와 M0의 같은 실제 시나리오 행동·비용·차량·안전 기록을 대조한다. 순수 검사에서는 계획·동률·양수 가중치의 가지치기도 검사한다.
2. 08-11·08-23의13시·18시×평가seed42~45에서5개 고정 모드를80회 비교한다. 원래 P0 경로에서 모드들의 첫 행동이 다른 시점이20개 이상, 조건2개 이상이어야 한다. 가장 좋은 고정 모드F를 고정한다(동률은 작은 번호).
3. 기존train13일에서08-11·08-23을 뺀11일로 seed42·42에피소드(30,240단계)를 학습한다. 개발 평가에서 P0/F 모두보다 평균 지연이 짧고 각각4조건 중3개 이상 개선되어야 확대한다. 좌회전·장기 대기·실행 완전성 조건도 적용한다.
4. 실측 학습·저장·평가 시간에25% 여유를 더해 전체가48시간에 들어가는지 계산한다. 부족하면 조건을 줄이지 않고 확대를 보류한다. 통과하면 seed42~46을 각각139에피소드(100,080단계)까지 학습한다. seed42는 이어 학습한다.
5. 09-28·08-13×07:30·12:30·17:30·21:30×평가seed1042~1049에서 P0/F/학습모델5개를 비교한다. F=M0이면 같은 기준 실행을 중복하지 않는다. 최대448회다.

새 실험의 성공은 P0와F 둘 다에 대해 평균 지연 감소, 학습seed와평가seed를 독립재표집한10,000회95%구간 하한>0, 학습5개 중4개 이상·수요8조건 중6개 이상 개선을 모두 요구한다. 차량수로 가중한 전체 평균을 사용하며 날짜·시간대는 재표집하지 않는 고정 조건이다. 재표집 난수는20261025다.

두 좌회전 평균 지연은 각 비교 대상보다5초 넘게 늘지 않고,300초 초과 대기 비율은 늘지 않아야 한다. 이 보조 조건은 같은 평가 조건을 합산한 값에 적용한다. 누락·미완료·실행 행동 오류·실제 규칙 보정·미확인 충돌이 있으면 채택하지 않는다. 정상적으로 규칙이 선택지를 하나로 남기는 것은 오류가 아니다. 충돌 원인을 추정만으로 예외 처리하지 않는다.

학습seed5개로 얻는 구간에는 작은 표본의 한계가 있다. 이미 사용한 날짜의 **추가 개발 확인 평가**이며 새 날짜 일반화 또는 실제 도로 성능이 아니다. 기존 실험의1.3초 판정을 사후 변경하지 않는다.

## 재개와 산출물

`experiment.json`은 설정·코드·환경·자료 지문, `budget.json`은 실패 작업도 포함한 누적 계산 장부다. 작업 시작 전에 시간 상한을 예약한다. 프로세스 중단으로 실제 시간 정산이 끊기면 재개 시 그 작업의 예약 상한을 보수적으로 청구해 예산 누락을 막는다.

`check.json`, `fixed_summary.json`, `pilot_summary.json`, `forecast.json`, `confirmation_summary.json`이 단계별 판단이다. `runs/`에는 원시 평가와 결정 기록, `training/`에는 학습별 차량·충돌·비용 정산 기록, `models/`에는 최신/직전 체크포인트와42·139에피소드 불변 사본을 보존한다. 종합 결과는 `summary.json`·`summary.md`다. 준비/실패/개발 결과를 성능 개선 완료로 표현하지 않는다.
