# WEIGHT1 긴 학습 — Colab 실행 안내

현재 강화학습이 짧게 배워서 M4를 못 넘었는지 확인하는 별도 실험이다. 원래 WEIGHT1의 pilot 미통과 결과는 보존한다. 학습 구조·보상·관측·행동·탐험 설정은 바꾸지 않는다. 오래 학습하면 좋아질 수 있지만 향상을 보장하지 않는다.

## 실행

1. Google Drive의 `MyDrive/FutureTraffic`에 `WEIGHT1_Long_Colab.ipynb`와 `FutureTraffic_WEIGHT1_Long.zip`을 둔다. 기존 `explore_weight_v1` 폴더는 그대로 둔다.
2. 노트북을 Google Colab으로 열고 CPU가 2개 이상인 런타임에서 위에서부터 모든 셀을 실행한다. GPU는 필수가 아니다. Drive 연결만 승인한다. 원래 실험의 패키지 버전이 맞지 않으면 노트북이 맞춰 설치하고 확인한다.
3. 실행 셀에서 프로필과 `LONG seed...` 진행 기록이 나오는지 확인한다. 실행을 시작한 뒤에는 자동으로 학습·개발 비교·조건부 확인 평가를 진행한다. 로컬 맥에서는 학습하지 않는다.

같은 결과 폴더를 쓰는 노트북을 여러 개 동시에 실행하지 않는다. 이 노트북 하나가 가능한 CPU 수에 맞춰 여러 학습 난수를 병렬 처리한다. 같은 폴더 중복 실행은 잠금으로 거부한다. 실행 중 노트북의 중지 버튼으로 중단하면 작업 프로세스를 정리한다. Colab 자체의 연결·자원 제공은 보장할 수 없다.

## 미리 고정한 학습량

| 자원 | 학습 난수 | 각 모델의 최종 학습 | 관찰 시점 |
|---|---|---|---|
| CPU 2개 | 42·43·44 | 278에피소드, 200,160단계 | 42·139·278에피소드 |
| CPU 3개 이상 | 42·43·44 | 417에피소드, 300,240단계 | 42·139·278·417에피소드 |

프로필은 새 실험 등록 시 자원만 보고 고정한다. 재개할 때 CPU 수가 달라져도 최종 목표는 바꾸지 않는다. CPU 1개에서는 시작하지 않는다. 한 작업자가 한 모델을 끝까지 독점하지 않고 최대 42에피소드씩 교대해 CPU 2개에서도 세 모델의 진도를 함께 올린다.

학습 난수 42는 기존 42에피소드의 모델·경험 저장소·난수 상태를 정확히 복사해 이어 간다. 43·44는 처음부터 독립적으로 학습한다. 원래 실험 폴더에는 쓰지 않는다. 모델 내부의 기존 실험 지문은 이어 학습의 동일성을 위해 유지하고, 별도 실험 지문과 계보 기록으로 이번 실험을 구분한다.

## 시간과 중단·재개

- 한 번 실행의 벽시계 시간 상한은 24시간이다. 이전 Colab 약 5시간과 취소된 맥 약 0.85시간을 포함한 전체 계산 상한은 96 작업시간이다. 병렬로 2시간씩 세 작업을 하면 6 작업시간으로 계산한다.
- 기존 실측 속도로는 학습·개발 평가·확인 평가를 합쳐 약 21시간의 병렬 실행을 예상하지만, 속도와 실제 완료 시간은 보장하지 않는다. 25% 여유를 둔 누적 비용 예상이 한도를 넘으면 시작하지 않는다. 새 실행의 시간을 별도 장부에 쌓는다.
- 에피소드가 끝날 때마다 모델·저장소·난수 상태를 Drive에 저장한다. 시간 제한으로 멈추면 같은 노트북을 다시 실행한다. 끝낸 학습과 검증된 평가 캐시는 재사용한다. 현재 진행 중이던 미완성 에피소드는 다시 수행할 수 있다.
- 비정상 종료로 실제 사용 시간을 확인할 수 없는 작업은 예약한 시간 전체를 보수적으로 계산한다. 재개하면서 예산을 초기화하지 않는다.
- Colab Pro+도 충분한 컴퓨팅 단위가 있어야 최대 24시간 실행할 수 있다. 런타임이 더 일찍 종료되면 저장된 상태에서 재개한다. 제한 회피나 연결 유지 장치는 사용하지 않는다. 근거: https://research.google.com/colaboratory/faq.html

## 무엇을 비교하는가

중간 점수는 학습곡선을 보기 위해 기록한다. 점수가 낮다는 이유로 최종 학습 전에 성능 기준으로 탈락시키지 않는다. 결과가 좋았던 중간 모델을 최종 모델로 고르지도 않는다.

개발 비교는 08-11·08-23 × 13시·18시에서 수행한다. 중간 관찰은 평가 난수 42·43, 최종 주 비교는 42~45다. 원래 P0와 고정 M4의 기존 개발 원시 자료는 지문·해시·차량 짝을 확인한 후 재사용한다. 최종 개발 비교에서 다음을 모두 충족해야 확인 평가로 진행한다.

- 세 모델 합산 평균이 P0와 M4 모두보다 낮다.
- 두 비교 각각 모델 3개 중 2개 이상, 날짜·시간대 4조건 중 3조건 이상에서 개선한다.
- 양쪽 좌회전 평균 지연이 비교 대상보다 각각 5초 넘게 늘지 않고, 300초 초과 대기 비율이 늘지 않는다. 차량 누락·미완료·규칙 오류·미확인 충돌이 없어야 한다.

통과한 경우 미리 정한 최종 모델 세 개를 고정하고 09-28·08-13 × 07:30·12:30·17:30·21:30 × 평가 난수 1042~1049에서 P0·M4·모델 3개를 비교한다. 최대 320회다. 성공은 두 비교 모두 평균 개선, 학습 난수와 운전자 난수를 각각 재표집한 10,000회 부트스트랩 95% 구간 하한 양수, 모델 3개 모두 및 8조건 중 6조건 이상 개선, 같은 악화 방지·완전성 조건을 충족하는 것이다.

학습 난수 세 개는 다섯 개보다 근거가 제한된다. 날짜·시간대 여덟 조건은 고정하며, 64회를 서로 독립적인 수요 표본으로 취급하지 않는다. 과거 사용한 날짜의 추가 개발 확인 평가이며 새 날짜 일반화나 실제 도로 성능을 뜻하지 않는다.
