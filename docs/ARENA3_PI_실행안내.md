# ARENA3 정책 반복 1라운드 실행 안내 (2026-10-31, 진행 기록 235·236절)

## 한 줄 요약

지금 가장 좋은 학습 정책(S2A_pre)이 운전하는 동안, 고를 수 있는 순간마다 **허용된 녹색을 모두 같은 미래로 굴려 비교**하고, 그 결과로 신경망이 **더 나은 녹색을 직접 고르도록** 배운다. 이것이 강화학습의 **정책 반복**이다. 다음 라운드에서는 이번에 배운 신경망이 운전한다.

## 왜 이렇게 하나

- 지금까지 성능을 실제로 올린 것은 SUMO 안에서 같은 순간을 되돌려 후보를 비교한 자료뿐이었다.
  - B′(탐색 제어): M4보다 +0.95초.
  - 그 자료를 흉내 낸 S2A_pre: +0.60초.
  - 한 번 지나간 판의 보상으로 배운 DQN·PPO: 선택 감각 0.0~0.24, M4와 구분되지 않음(234절).
- 지금 행동(좌회전 가중 고르기)에는 여지가 작다. 실측해 보면 한 시간 720번의 결정 가운데:
  - 632번은 허용 녹색이 하나뿐이라 고를 것이 없다.
  - 29번은 갈림 지점(모드들이 다른 녹색을 냄)이다. 지금 RL은 여기서만, 그것도 거의 둘 중 하나를 고른다.
  - 59번은 합의 지점(고를 수 있는데 여섯 모드가 모두 같은 녹색)이다. 지금 RL은 여기서 아무것도 고르지 않는다.
  - 갈림 지점에서도 어느 모드도 내지 않는 허용 녹색이 평균 1.9개 있다.
- 그래서 학습 방법(같은 순간 짝 비교)과 행동(녹색 직접 선택)을 함께 바꾼다.

## 무엇을 하나

| 단계 | 내용 |
|---|---|
| 지금 정책 | S2A_pre 난수 42. 개발 판정을 통과한 학습 모델 가운데 날짜 평균이 가장 큰 방식(+0.599초)의 첫 난수다. 난수는 성적이 아니라 순서 규칙으로 골랐다. |
| 학습 상황 | 학습 8일 × 날짜마다 15분 칸 8개 = 64판. 도착 배치는 새로 만든다(B′ 자료와 다름). 평가 날짜는 쓰지 않는다. |
| 결정 지점 | 갈림 지점은 모두, 합의 지점은 해시 규칙으로 25%만 고른다. |
| 후보 | 그 순간 허용된 녹색 전부(갈림 평균 3.9개, 합의 평균 3.4개). |
| 굴리기 | 같은 표본 미래 8개로 300초씩 굴린다. 첫 5초는 후보 녹색, 그 뒤는 지금 정책, 제어 60분이 끝나면 P0이다(본 에피소드와 같다). 비용은 B′와 같다(300초 지연 + 남은 정체 × 75초). |
| 본 에피소드 | 행동은 언제나 지금 정책의 선택이다. 롤아웃 결과를 기다리지 않는다. 그래서 자료는 '지금 정책이 실제로 가는 상태'에서 모인다. |
| 학생 | 관측 119칸만 보는 64-64 신경망이 녹색 4개의 값(M4 녹색 대비)을 출력한다. 짝 평균 이득을 S2A와 같은 신뢰 가중 Huber로 배운다. 목표는 교사 규칙 c=0이다(225절). 난수 42·43·44로 3개를 만든다. |

| 심판 | 1단계와 같은 84상황과 같은 판정(M4 대비)을 쓴다. 승자만 C1·C2 84상황에서 한 번 더 확인한다. |

최종 제어기는 신경망뿐이다. 실행 때 탐색은 하지 않는다. 롤아웃은 학습 자료를 만들 때만 쓴다.

## 실행 방법

1. Drive `FutureTraffic/`에 `FutureTraffic_ARENA3_PI.zip`과 노트북 네 개(자료 조각 0·1·2, 학습·평가)가 있다.
2. **자료 모으기**: 조각 0 = `ARENA3_PI_R1_data.ipynb`, 조각 1 = `ARENA3_PI_R1_data_shard1.ipynb`, 조각 2 = `ARENA3_PI_R1_data_shard2.ipynb`
   - Colab은 같은 노트북 파일을 탭 여러 개로 열어도 런타임 하나에 붙는다. 그래서 조각마다 파일을 따로 두었다(236절의 처음 안내 "한 파일을 런타임 3개에서"는 틀렸다, 237절).
   - 세 파일을 하나씩 열어(CPU + 높은 RAM) 각각 **모두 실행**한다. `SHARD`는 파일마다 이미 정해져 있어 바꾸지 않는다.
   - 같은 조각을 두 런타임에서 동시에 돌리지 않는다(같은 결과 파일을 서로 덮어쓴다).
   - 런타임 4개로 나누고 싶으면 조각 파일을 새로 만들어야 한다(요청하면 준비).
   - 실행 전 점검이 약 15분 걸린다. 같은 판을 그냥 돌린 것과 상태 저장·롤아웃을 하며 돌린 것이 소수점까지 같은지, 복원이 맞는지 보고, 판당 시간을 잰다.
   - 본 수집은 런타임 3개 기준 약 15~17시간이다(어림: 판당 약 5.7 CPU-시간 × 64판 ≈ 365 CPU-시간). 점검 칸이 실제 값으로 다시 어림한다.
   - 끊기면 다시 **모두 실행**한다. 끝난 판은 건너뛰고, 끊긴 판만 처음부터 다시 한다.
3. **학습·평가·판정** `ARENA3_PI_R1_learn.ipynb`
   - 64판이 끝나면 런타임 하나에서 **모두 실행**한다.
   - 순서: 날짜 보류 진단(참고, 약 10분) → 학생 학습(약 5분) → 평가 756판(약 5~6시간) → 판정 → 확인(통과한 변형이 있을 때만, 약 2시간).
   - 첫 칸이 자료 64판이 다 끝났는지 확인하고, 아니면 멈춘다(일찍 열어도 안전).
   - 노트북 소개의 "다른 런타임 두 곳에서 이 노트북을 열고 VARIANTS를 바꿔"는 같은 이유로 그대로는 안 된다. 한 런타임에서 순서대로 돌린다. 평가를 나눠 빨리 끝내려면 평가용 파일을 따로 만들어야 한다(요청하면 준비).
4. 결과 위치: Drive `arena3/pi/R1/`
   - `data/`: 자료
   - `offline/`: 날짜 보류 진단
   - `students/`: 학생 모델
   - `eval/R1M·R1G·R1A/`: 평가
   - `judge/summary.md`: 판정
   - `judge/confirm/`: 확인

## 미리 정한 판정·읽는 법(결과를 보기 전에 고정)

- **주 판정**: 각 변형을 M4와 비교하는 ARENA3 판정 그대로다. 다음 조건을 모두 만족해야 한다.
  - 날짜 평균 ≥ 0.3초, t95 하한 > 0, 양수 날짜 ≥ 5.
  - 좌회전 지연이 M4 + 5초 이내.
  - 300초 초과 대기 차량 수가 M4 이하.
  - 정책 고유 충돌 0, 품질 오류 0.
- **짝 비교**: 같은 84상황에서 날짜 7개의 차를 구하고 t95(자유도 6)로 읽는다.
  - `R1M − S2A_pre`: 정책 반복 1라운드가 출발 정책보다 짧은가(지금 행동 범위).
  - `R1G − R1M`: 갈림 지점에서 모드 밖 녹색까지 고르는 몫.
  - `R1A − R1G`: 합의 지점에서도 고르는 몫.
  - 각 변형 − S2B: 지금까지 통과한 유일한 RL 결과와 비교.
  - 각 변형 − B′: 탐색 제어와 비교.
  - 읽기: t95 하한 > 0이면 "앞쪽이 짧다", 상한 < 0이면 "앞쪽이 길다", 그 사이면 "구분 못 함".
- **승자와 확인**: 주 판정을 통과한 변형 가운데 날짜 평균이 가장 큰 것 하나만 C1·C2에서 한 번 잰다. 승자는 처음 한 번 정해지면 다시 고르지 않는다. 확인에서는 S2B의 C1·C2 결과와도 짝 비교한다.
- **다음 라운드**: 확인까지 통과한 승자의 난수 42 모델이 2라운드의 지금 정책이 된다. 통과가 없으면 2라운드 설계는 결과를 보고 다시 정한다.
- **날짜 보류 진단**은 참고용이다. 판정과 모델 선택에 쓰지 않는다.

## 자료 품질 규칙

- 복원 확인: 결정 지점마다 '실제 미래 5초 재생'이 본 에피소드와 같은지 본다(허용 오차 1e-6).
  - 불일치한 지점은 학습에서 뺀다.
  - 모든 조각을 합해 200지점 이상에서 불일치가 8%를 넘으면 새 판을 시작하지 않는다.
  - B′ 자료의 불일치는 약 3%였다. 조각마다 따로 세면 우연히 넘을 수 있어 합해서 센다(210절).
- 롤아웃 안에서 미래 엿봄이나 규칙 변경이 하나라도 나오면 그 판은 실패다.
- 실패한 롤아웃
  - 판의 2%(최소 3개) 이하이면 그 미래를 모든 후보에서 빼고 오류를 적는다.
  - 2%를 넘으면 그 판은 실패다.
- 충돌
  - 어느 후보에서든 미확인 충돌이 난 미래는 모든 후보에서 뺀다.
  - 본 에피소드에 미확인 충돌이 나면 그 판의 지점은 모두 뺀다(기록함).

## 바꾸지 않은 것

- ARENA3 잠금, 심판, 환경 파일, 기존 결과 폴더.
- 새 코드: `src/arena3_pi.py`(수집·정책), `src/arena3_pi_learn.py`(자료·학생·평가·판정)
- 새 설정: `config/arena3_pi_r1.json`
- 새 시험: `tests/test_arena3_pi.py`
- 실행기(`run_arena_episode`)는 P0 종류의 정책만 모든 제어 단계에서 부른다. 그래서 모든 단계를 봐야 하는 수집기와 평가 정책은 그 종류로 둔다.
  - 실행기 코드는 그대로다.
  - P0 일치 검사 값(`p0_mismatch`)은 늘리지 않는다.
  - 점검 칸이 '그냥 돌린 것과 같은가'를 확인한다.

## 보고할 때

- 반복 사용 날짜의 개발 비교다. C1·C2는 같은 7일의 새 도착 배치일 뿐, 새 날짜나 실제 도로에서의 일반화는 검증하지 않았다.
- 학생은 정책 반복으로 배운 신경망이다. 교사(롤아웃 비교)는 학습 자료를 만들 때만 쓴다.
- 결과가 기대보다 작으면 '시험한 설정의 성능 정체'로 쓰고, 원인을 하나로 단정하지 않는다.
