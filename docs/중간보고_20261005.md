## 3. 석천사거리 단독 모형에서 고친 것

| 문제 | 원인 | 결과 |
|---|---|---|
| 녹색이 잘리거나 황색 없이 적색 | 15분 신호 파일을 잘못 이어 붙임 | 하루 시간축으로 복원. 19일 전체 황색 없는 전환 0 |
| 6분 가까운 녹색이 기록됨 | 신호 기록 누락(같은 시간에도 석천로 차량이 평소대로 통과) | 주변 주기로 채우고 그 시간대를 표시(15곳) |
| 좌회전 버스 때문에 영구 교착 | SUMO가 버스·트럭·이륜차는 앞길을 383m만 내다봄 | 차로를 미리 잡는 거리 3,000m → 교착 사라짐 |
| 서쪽 접근로 평일 아침 정체 붕괴 | 실제로 54%가 오는 다른 길주로 가지를 경로에 넣지 않음 | 상류 기록 비율로 두 갈래에 나눔 |
| 실제 통과량을 못 따라감 | SUMO 기본 운전자 설정(무작위 감속)이 처리 능력을 낮춤 | 학습·검증 날짜로 보정(무작위 감속 0) |

- 결과: 학습·검증 15일을 하루씩 끊지 않고 돌려 모두 미진입 0, 충돌 0, 순간이동 0. 하루 차량당 지연 42.6~53.1초.
- 교차로 내부 충돌 검사(처음 검증에서 빠졌던 항목)를 켜고 3일(08-11, 09-06, 09-28)을 다시 돌려도 충돌 0이었다.
- **예전 결과에 준 영향**: 같은 차량·같은 seed로 신호만 고치자 기존 고정신호 52.4초 → 50.4초. DQN 개선 폭 −19.7% → **−16.6%**. 도로 진입 전 대기까지 넣어 5분 이상 기다린 차량을 다시 세면 고정신호 407 → 689대, DQN 2,764 → 2,963대(학습 1회당)로 DQN의 장기 대기 문제는 그대로다.

## 4. 새로 확인된 문제

### 4.1 석천사거리 모형의 학습·집계 코드 (학습 전에 반드시 고칠 것)

1. **새로 넣은 갈래를 DQN이 보지 못함**: 서쪽 접근로 차량의 54%가 쓰는 584m 갈래가 관측·보상·대기열 집계에서 빠졌다(정지한 59대를 점수에서 놓친 재현). 3절 작업에서 생긴 실수다.
2. **실행할 수 없는 신호를 미래의 좋은 선택으로 계산**: 최대 녹색·보행 대기 규칙 때문에 막힌 행동의 값을 학습 목표에 쓴다.
3. **예전 결과 재사용**: 수요·설정·모델이 바뀌어도 기존 파일이 있으면 그대로 쓴다.
4. **기본 학습 명령의 날짜 누출**: 날짜 분할을 지정하지 않으면 시험·검증 날짜가 학습에 들어간다(기존 모델은 분할을 지정해 문제없음).
5. **집계 정의**: 5분 이상 대기에서 진입 전 대기 누락, 교차로 안에 들어간 차를 회전 완료로 셈, GEH 비교의 시간 단위 오류(고쳐 다시 세도 15일 모두 기준 통과).

### 4.2 전체 설계

- **범위 축소**: 석천사거리 단독 모형은 주변 교차로 교통을 지운 예비 모형이다. 상류 신호가 보내는 차량 무리, 다른 길에서의 합류, 하류 정체가 밀려오는 효과가 빠진다.
- **처음의 미반영 59건은 해결되지 않았다**: 단독 모형에서는 범위 밖으로 뺐을 뿐이다.
- **경로 과다 배정**: 같은 15분 표본에서 기록 1,628회에 대응하는 이동을 생성 경로가 3,178회 지나도록 되어 있었다. 빠진 양만 검사해서는 넘친 양을 놓친다.
- **자료의 성격**: 12곳 중 9곳만 실제 수집 대상이고 3곳(넘말·복사골·영안)은 연결을 위해 추가한 곳이다. 제공 궤적·OD는 SUMO로 가공한 결과라 지도를 검증하는 독립 정답이 아니다.
- **상류 연동**: 석천사거리와 주기가 같은 이웃 신호는 동쪽 204822뿐이다(1,824개 시간대의 97%). 남쪽 201292·서쪽 송내·204920은 주기가 달라 연동이 아니다. 지금처럼 15분 동안 무작위로 도착시키면 동쪽 접근로에서 실제 고정신호가 얻는 연동 이득이 빠지고, 그만큼 DQN에 유리한 비교가 된다.

## 5. 12개 교차로 전체 모형 (현재 상태)

- 162개 이동의 지도 대응표, 도로망 경계에서 들어와 나가는 경로, 원본 수량·부족·초과를 함께 보는 검사, 교차로 내부 충돌 검사, 결과 재사용 방지를 만들었다. 지도 원본은 보존하고 가정은 사본으로만 시험한다.
  - 중앙공원(201306)의 빠진 연결 2개를 사본에 복원해 차량이 지나가는 것을 확인했다.
  - 0.29m짜리 도로로 이어진 비신호 교차로 두 곳이 서로 막던 교착을 그 지역만 합친 사본으로 풀었다.
  - 버스가 교차로 안에서 기다리는 위치 때문에 생긴 겹침(충돌로 검출)을 대기 위치를 1m 옮긴 사본으로 줄였다.
- **첫 시험(2022-08-11 05:00~06:00, 학습 날짜)**: 5,107대 모두 도착, 미진입 0, 충돌 1건(204822 교차로 안에서 멈춘 트럭과 지나가던 버스의 차체 겹침. 앞선 4건과 같은 유형으로 보이나 원인은 미확정).
- '회전량 오차 15%'의 의미: 15분×차종×이동처럼 아주 잘게 나눈 값이다. 같은 단위에서는 우연한 흔들림만으로도 약 20%가 나온다. 1시간×이동으로 보면 153개 이동 중 3개만 크게 어긋난다.
  - 201293 유턴: 의미가 확인되지 않아 보류, 관측 157 → 모의 0
  - 송내 교차로의 한 이동: 관측 87 → 모의 208
  - 중앙공원의 한 이동: 관측 22 → 모의 53
- **가장 큰 공백**: 이 시험은 12개 교차로 모두 **지도에 내장된 신호**를 썼다. 석천사거리도 실제 운영(첨두 주기 약 200초) 대신 90초 주기·좌회전 6초 신호다. 실제 신호는 전체 모형에 아직 들어가지 않았다. 신호 칸 수가 지도와 다른 곳이 3곳이고, 다른 교차로의 실제 신호 해석(석천사거리에서 확인한 '한 현시 밀림'이 다른 곳에도 맞는지)도 확인 전이다.
- 수요가 적은 새벽 1시간만 시험했다. 출퇴근 첨두에서는 아직 확인하지 않았다.

## 7. 다음 순서 (제안)

1. **석천사거리 모형의 코드 결함 5건 수정**: 작고 확실한 작업이다. 전체 모형이 늦어져도 믿을 수 있는 비교 하나는 남는다.
2. **전체 모형에 실제 신호 적용**: 석천사거리(해석 확인됨)와 204822(같은 방법으로 해석 확인)부터 넣어 연동을 재현한다. 나머지는 확인된 곳부터 넣고, 확인 안 된 곳은 내장 신호로 두되 표시한다.
3. **첨두 시간 시험**: 학습 날짜의 07~09시·17~20시로 전체 모형을 검증한다. 통과 기준(미진입·충돌·시간별 회전량·방향별 대기)은 시험 전에 정한다.
4. **남은 자료 문제는 가정형으로 비교**: 유턴, 신호 칸 3곳, 송내 과다 배정은 가정을 바꿔 돌렸을 때 결론이 달라지는지 확인한다.
5. **환경 고정 → DQN 재학습·비교**: 고정신호·감응식·DQN을 같은 수요·운전자·규칙에서 비교한다. 평균 지연과 함께 방향별 장기 대기, 진입 전 대기, 보행 서비스, 완료율, 운전자 설정 민감도를 보고한다.

## 8. 끝내는 기준과 일정 위험

- 자료 한계(실제 차량 경로·대기 자료 없음, 3곳 비수집, 유턴 의미 미확인) 때문에 '가정이 하나도 없는 환경'은 만들 수 없다. 끝내는 기준은 **남은 가정이 설명되고, 그 가정을 바꿔도 결론이 유지되는지 확인된 상태**다.
- 전체 모형은 남은 일이 많다. 기한 안에 첨두 검증을 통과하지 못할 경우를 대비해, 석천사거리 단독 모형(결함 수정 + 204822 연동 도착 추가)을 예비 비교로 함께 유지하는 것을 권한다.
