# M4 저장 상태 복원 오류 진단 및 재개

기존 20220812 07:30 난수 43의 첫 선택 상태 복원 검사에서 오류가 났다. 기존 코드는 신호·관측·차량 상태 중 어느 부분이 달랐는지 남기지 않았기 때문에 정확한 원인은 아직 확인되지 않았다. `Retrying in 1 seconds`는 SUMO 연결 과정에 출력되는 재시도이며, 실제 중단 이유는 그 뒤의 저장 상태 복원 불일치다.

새 `M4PROBE_RESTORE_Colab.ipynb`는 기존 진단의 저장된 성공 결과를 지문과 해시로 검증해 재사용하고, 실패했던 상황부터 한 번 더 확인한다. 선택 후보, 110칸 관측, 마스크, 허용 행동, 초기와 5초 후 차량 ID·차로·위치·속도·신호 및 진입 대기를 비교한다. 오류 시 `explore_m4probe_v1/restore_diagnostics/20220812_0730_s43.json`에 차이와 예시를 남긴다. 원래 복원 검사는 완화하거나 건너뛰지 않는다. 실패하면 그 자리에서 멈추고, 해당 상황을 제외하고 결과를 만들지 않는다.

사용자의 새 요청에 따라 5작업시간·누적 96시간·12시간 벽시계 한도와 540초 에피소드 계산 시간 제한, 예산 추정에 따른 자동 중단을 이 재개 실행에서 없앴다. 300초 시뮬레이션 길이는 연구에서 비교할 범위를 정한 값이라 그대로다. 기존 실험의 상황·난수·후보·선정 방식·판정과 지문을 바꾸지 않는다. 기존 장부는 보존하고 재개 코드 지문 및 재개 기록을 별도 저장한다. Colab 연결이 끊어지면 이전에 완료한 상태를 검증 후 재개한다. 동일 결과 폴더를 두 런타임에서 동시에 실행하지 않는다.

## 실행

1. 오류가 난 기존 노트북이 중단된 상태인지 확인한다.
2. Drive `MyDrive/FutureTraffic`에서 `M4PROBE_RESTORE_Colab.ipynb`를 Colab으로 열고 CPU 런타임을 선택한다. `FutureTraffic_M4PROBE_RESTORE.zip`과 이전 결과 폴더들은 같은 위치에 둔다.
3. **런타임 → 모두 실행**을 누른다.
4. 실패했던 상황이 다시 실패하면 오류 메시지와 진단 파일이 남는다. 오류가 발생했다고 알려 주면 Drive의 진단 파일을 확인해 원인을 분석한다. 이 경우 전체 진단이 자동으로 넘어가지 않는다.
5. 실패 상황이 통과하면 나머지 상태 수집과 독립 표본 미래 비교를 자동으로 이어간다. 끝나면 알려 준다.

실제 Colab의 복원·표본 미래 실행은 이 파일로 처음 확인한다. 검증 없이 우월성이나 실제 도로 성능을 주장하지 않는다.
