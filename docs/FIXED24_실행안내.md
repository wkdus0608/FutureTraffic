# 고정 가중치 24상황 비교 — Colab 실행 안내

이 실험은 RL을 다시 학습하기 전에 강한 고정 비교 기준 후보를 찾는다. 11개 RL 학습 날짜의 24개 시간대에서 P0·M4·4배·6배·8배를 동일한 차량·경로·난수로 각 24회(총 120회) 비교한다. 사전에 정한 전체 차량당 평균 지연 기준으로 후보를 선택한다. 동률은 P0→M4→4→6→8 순이다. 누락·미완료·정산 오류·미확인 충돌·차량/경로 짝 불일치 등은 자동 선택 전에 중단한다. 장기 대기·좌회전 지연은 결과에 보고하고, 최종 성능 채택 판정으로 오인하지 않는다.

선택 후보가 4·6·8배이면 과거 09-28·08-13의 64조건에서 후보만 새로 실행해 기존 P0·M4·RL 3개 원시 결과와 비교한다. P0 또는 M4가 후보면 과거 64조건 결과를 재사용한다. 기존 원시 결과의 지문·해시·모델 식별·차량/경로·충돌 판정 범위를 검증한다. 이전 64조건의 미확인 충돌 등 품질 문제는 그대로 표시하고 감추거나 제외하지 않는다.

## Colab에서 실행

1. Drive `MyDrive/FutureTraffic/`의 `FIXED24_Colab.ipynb`를 Colab에서 연다. 같은 폴더에 `FutureTraffic_FIXED24.zip`, 기존 `explore_night_v1`, `explore_weight_resume_v1`, `explore_weight_v1`이 있어야 한다.
2. 런타임 유형을 **CPU**로 선택하고 **런타임 → 모두 실행**을 누른다.
3. 먼저 패키지와 코드 검사를 한 뒤 첫 상황의 5개 정책을 실행한다. `첫 상황 5정책 실행·차량 짝·정산 검사 통과`가 보이면 나머지가 자동으로 이어진다. 이 5회는 120회에 포함된다. 오류가 보이면 로그를 알려 준다.
4. 결과는 Drive `FutureTraffic/explore_fixed24_v1/summary.md`, `summary.json`, `runs/`, `budget.json`에 저장된다. 연결이 끊기면 같은 노트북에서 다시 모두 실행하면 완료된 결과를 검증 후 재사용한다. 미정산 작업은 최대 예약 시간으로 보수적으로 계산한다.

같은 출력 폴더에 대해 Colab 런타임 두 개를 동시에 실행하지 않는다. 한 런타임 안에서는 CPU 작업자가 최대 4개까지 동시에 실행된다.

기존 누적 96작업시간 한도를 유지한다. 184회 기준 이전 실측으로 약 8.4작업시간이지만 속도·실패에 따라 달라지고 한도 때문에 중단될 수 있다. 이 경우 더 작은 표본을 성공으로 판정하지 않는다. 동시 실행도 작업시간에 합산하며 5분과 진행 중인 작업의 예약 시간을 남기고 새 작업을 시작하지 않는다. 실행당 시간 상한은 570초다. 실제 Colab의 벽시계는 CPU 수와 런타임 속도에 따라 달라진다. 맥에서 시뮬레이션을 시작하지 않는다.

## 해석

24상황은 학습 날짜를 재사용하는 개발 비교, 기존 64조건도 이전에 사용한 날짜의 추가 개발 비교다. 독립적인 최종 검증이나 실제 도로 성능이 아니다. 날짜마다 여러 시간대가 있어 24개가 독립적인 날짜 24개를 뜻하지 않는다. M4 대비 날짜 단위 10,000회 재표집 구간은 탐색용이며 후보 선택 편향과 날짜 선정의 한계가 있다. 사후 최적 고정 정책과 RL의 비교는 동적 RL 성능의 상한이 아니며 0.5초 차이를 검출한다고 보장하지 않는다. RL 재설계·학습·최종 검증은 별도 실험 및 예산이 필요하다.
