# M4 선택 지점 파일럿 — FIXED2 실행 안내 (2026-10-27)

## 왜 필요한가

Colab에서 저장 상태 복원 검사(`저장 상태 복원이 원래 M4와 다릅니다`)가 20220812 07:30 난수 43 상황에서 반복해서 실패했다. 진단 파일을 보면 원인은 하나였다: 저장 시점에 "도로에 들어오려고 기다리는 차량"(진입 대기) 한 대가 있었는데, 복원한 SUMO는 불러온 직후 첫 단계 전까지 그 차량을 대기 목록에 올리지 않는다(5초 뒤에는 모든 것이 같다). SUMO 원본 소스로도 확인했다: 대기 목록(`myPendingEmits`)은 상태 파일에 저장되지 않고, 불러온 차량은 첫 단계에서 대기 목록으로 옮겨진다. 차량의 출발 지연값(`getDepartDelay`)은 `현재 시각 − 출발 시각`이라 원본과 복원본이 같다.

FIXED(200절)의 수정은 이 사실에 맞다: 복원 직후 한 순간의 대기 목록 조회만 저장 당시 값으로 보완하고, 그 뒤 300초를 매 5초 원본과 비교한다. FIXED2는 같은 수정에 아래만 더했다.

- 실패하면 **무엇이 달랐는지**(관측 몇 번 칸, 대기 목록, 차량 위치·속도)를 파일과 화면에 남긴다. FIXED는 오류 문장 한 줄만 남긴다.
- 한 상황이 실패해도 **나머지 15개 상황을 끝까지 검사**하고 `restore_report.json`에 통과·실패를 모은다. 한 번 실행으로 모든 문제를 본다.
- 실패한 상황의 저장 상태와 비교 기록을 `restore_failed/`에 보존한다(맥에서 열어 볼 수 있다).
- 하나라도 실패하면 후보 비교(롤아웃, 수 시간)를 시작하지 않고 멈춘다. 아무것도 버리거나 건너뛰지 않는다.
- 전부 통과하면 기존 코드(`explore_m4probe_repaired.py`)가 그대로 이어받는다.

통과 기준(관측 110칸·모드 행동·마스크·허용 현시·실행 현시·차량/신호/대기 지문이 300초 동안 매 5초 같을 것)은 한 글자도 완화하지 않았다. 상황·상태·후보·표본 미래·판정은 모두 기존 사전 계획 그대로이고, 실험 지문도 같다.

## 실행

1. Drive `MyDrive/FutureTraffic/`의 `M4PROBE_FIXED2_Colab.ipynb`를 Colab에서 연다(CPU 런타임). 같은 폴더에 `FutureTraffic_M4PROBE_FIXED2.zip`과 `explore_weight_v1`, `explore_fixed24_v1`, `explore_night_v1`이 있어야 한다. 이전에 실행 중인 RESTORE/FIXED 노트북은 먼저 중지한다.
2. **런타임 → 모두 실행**. 결과 폴더는 `explore_m4probe_pending_v1`이며 FIXED와 같다(이미 검증된 상황은 재사용된다).
3. 몇 분 안에 `실패했던 상황의 300초 복원 검증 통과` 또는 `다시 실패했습니다`가 나온다. 그 뒤 나머지 상황을 검사하고 `복원 검증 요약: 통과 N, 실패 M`을 출력한다.
4. 실패했다면 마지막 셀의 출력 전체를 알려 준다. 화면에 관측 차이·대기 목록·차량 차이가 요약되어 있다.
