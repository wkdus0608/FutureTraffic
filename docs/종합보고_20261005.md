## 4. 범위 결정 — 석천사거리 먼저, 12개 교차로는 보류

- 원래 계획은 12개 교차로 지도에서 석천사거리만 DQN이 제어하는 것이었다.
- 12개 모형은 나머지 11곳의 신호 해석, 차량 경로 추정(자료가 교차로별 장부라 차를 이을 수 없음), 출퇴근 시간 검증이 남아 기한 예측이 어렵다.
- **왜**: 질문에 답하는 데 꼭 필요한 것은 "같은 수요·같은 운전자·고장 없는 도로·공정한 채점"이다. 석천사거리 모형으로 이것을 먼저 갖춘다. 12개는 포기가 아니라 보류이며, 나중에 결과를 넓은 지도에서 보여 주는 확장으로 쓴다.

# 2부. 우리 코드가 정한 규칙 전체

## 10. 차량(수요) 규칙 — `focused_scenario.write_routes`

| 규칙 | 값 | 왜 |
|---|---|---|
| 기록 1건 = 차 1대 | 하루 7~11만 대 | 기록된 수요를 빠짐없이 그대로 |
| 도착 시각 | 이동별 15분 대수를 그 15분 안에 무작위로 | 1분 기록에는 실제 신호 시점이 찍혀 있어 그대로 쓰면 고정신호에 유리 |
| 같은 난수 | 날짜·시간대마다 고정된 난수 | 모든 신호 방식이 똑같은 차를 받게 |
| 경로 | 상류 직진 도로 → 교차로 → 하류 직진 도로. 상류 최대 약 300m, 하류 150m, 다음 신호 앞에서 끊음 | 다른 신호의 영향을 받지 않게 |
| 서쪽 두 갈래 | 상류 기록 비율대로(약 45%·55%). 우회전은 4차로 가지, 좌회전·유턴은 2차로 가지 | 없는 병목을 만들지 않게(회전별 배정은 가정) |
| 출발 | 정지선 도착 시각에서 자유 주행 시간만큼 앞당김. 차로는 가장 알맞은 곳, 속도는 최고 | 정지선 도착 시각을 맞추기 위해 |
| 차종 | 승용·버스·트럭·이륜(AI Hub 기록대로) | |

## 12. 신호 규칙

**공통**: 녹색 4종류(석천로 좌회전, 길주로 직진, 길주로 좌회전+유턴, 석천로 직진). 우회전은 언제나 양보 녹색. 전 방향 적색 시간은 없다(실제 기록에도 없음).

| 신호 방식 | 규칙 |
|---|---|
| 고정신호 | 그날 실제 운영 신호를 그대로 재생("한 현시 밀림" 보정 + 하루 시간축 복원). 황색은 기록대로 4초(석천로 직진만 3초). 순서도 실제대로 |
| 감응식 | 실제 신호의 순서는 그대로. 녹색마다 최소(보행 46·33초, 그 밖 15초)~최대(그 시간대 실제 녹색 중앙값 × 1.25) 사이에서, 감지기에 차가 계속 들어오면 늘리고 끊기면 다음으로. 우회전 전용 차로 감지기는 끔. 황색 4초 |
| DQN | 5초마다 녹색 4개 중 하나를 고름(순서 자유). 바꿀 때 황색 4초. 아래 13절의 운영 규칙을 지킴 |

## 13. DQN이 지켜야 하는 운영 규칙 — `focused_rl.SignalConstraints`

DQN이 고른 신호는 실행 전에 아래 순서로 검사하고, 어기면 바로잡는다. 실제 신호도 지키는 규칙이라 DQN에게만 특혜를 주지 않기 위해서다. 바로잡은 횟수는 따로 센다.

| 순서 | 규칙 | 값 | 근거 |
|---|---|---|---|
| ① | 최소 녹색: 이 시간 전에는 바꿀 수 없음 | 석천로 직진 46초, 길주로 직진 33초, 나머지 15초 | 보행자가 건너는 시간 = 7초 + 횡단 길이 ÷ 1m/s(길주로 38.4m, 석천로 25.6m). 석천로 직진 46초는 실제 녹색 47초와 맞음 |
| ② | 보행자 최대 대기: 각 횡단보도는 이 시간 안에 다시 열려야 함 | 길주로 횡단 155초, 석천로 횡단 120초 | 실제 신호에서 같은 직진이 다시 켜질 때까지 걸린 시간의 99% 값. 앞으로의 최소 녹색까지 계산해 늦을 선택은 미리 막음. 급하면 가장 급한 횡단보도를 여는 신호로 바로 넘어감 |
| ③ | 최대 녹색: 같은 신호를 이보다 오래 유지 못 함 | 120초 | 실제 녹색 최대 106초보다 넉넉함 |
| ④ | 차량 최대 누적 대기(v5): 감지 구간 전체와 진입 대기 차 중 누적 대기(진입 전 대기 + 멈춘 시간 합)가 기준을 넘은 차가 있으면 그 차의 신호로 바꿈 | 165초 | 실제 신호에서 99%의 차가 이보다 덜 기다림. ①~③을 어기지 않을 때만 적용. 예전에는 '정지선 앞 차의 연속 정지 120초'였다 |

**예전 ④ 120초 규칙이 제 역할을 못 한 이유(v5에서 고침)**

- **맨 앞 차만 본다**: 규칙은 정지선 바로 앞 도로(11~19m, 차로마다 맨 앞 1~2대)만 본다. 줄 뒤쪽 차는 아무리 오래 기다려도 보지 않는다.
- **움직이면 0부터 다시 센다**: SUMO의 "기다린 시간"은 차가 조금이라도 움직이면 0으로 돌아간다. 줄이 조금씩 앞으로 가면 계속 0으로 돌아간다.
- **결과**: 줄 뒤쪽 차는 신호 몇 번에 걸쳐 합계 5분 넘게 기다려도 규칙에 걸리지 않는다. 예전 DQN이 길주로 동쪽 접근로 좌회전 차의 약 20%를 5분 넘게 세워 둔 이유 중 하나다.
- **고치는 방향(결정 B)**: 줄 전체를 보고, "멈췄다 움직였다를 합친 누적 대기 시간"으로 센다.

## 14. DQN이 보는 것·받는 점수·배우는 방식 — `focused_rl.py`, `focused_train.py`

| 항목 | 규칙 |
|---|---|
| 보는 것(숫자 64개) | 지금 녹색(4), 최소 녹색을 채웠는지(1), 녹색이 얼마나 지났는지(1), 정지선 앞 차로 20개의 밀도·대기(40), 접근로 4개의 상류(서쪽은 두 갈래 모두) 차량·정지 비율과 진입 대기(12), 횡단보도 2개의 보행 대기(2), 그대로 실행될 행동 표시(4) |
| 점수(보상) | −0.1 × (멈춘 차 + 도로에 못 들어온 차). 많이 막힐수록 낮음 |
| 점수의 약점 | 차 수의 합만 보므로, 차가 적은 방향(예: 좌회전)을 오래 세워도 점수가 크게 나빠지지 않는다 → 13절 ④와 함께 장기 대기의 원인 |
| 기억하는 행동 | DQN이 고른 행동이 아니라 실제로 켜진 신호(규칙이 바꿨을 수 있으므로) |
| 미래 가치 계산 | 관측 끝 4칸의 '그대로 실행될 행동' 표시 중에서만 최댓값을 씀(v5). 규칙으로 막힌 신호의 값은 배우지 않음 |
| 행동 선택 | 같은 표시 안에서 Q값이 가장 큰 신호를 고름. 탐험(무작위)도 그 안에서(10-06). 그래서 고른 신호가 그대로 켜지고, 학습 목표가 가정하는 행동과 실제 행동이 같다 |
| 연습 방식 | 학습 13일에서 시각을 무작위로 골라, 실제 신호로 30분 돌려 대기열을 만든 뒤 녹색 시작에 넘겨받아 60분 연습(v5). 중간 저장을 덮어써 끊겨도 이어서 학습 |
| 학습 설정 | 학습률 0.001, 경험 저장 10만 개, 1,000번 뒤부터 학습, 64개씩 묶어 학습, 처음 20% 동안 탐험을 1 → 0.05로 줄임 |
