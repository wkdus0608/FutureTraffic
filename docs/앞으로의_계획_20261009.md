## 4. 작업별 자세한 내용

### A. DQN 구조 질문에 답하기 (10/15까지)

#### A-1. 사실 정리 (코드와 라이브러리에서 확인함, stable-baselines3 2.9.0)

| 질문 | 답 | 근거 |
|---|---|---|
| 신경망 모양은? | 입력 64 → 은닉층 64 → 은닉층 64 → 출력 4. 은닉층이 2개이고 층마다 칸(노드)이 64개다. "64 layer"가 아니라 "64칸짜리 층 2개"다 | SB3 기본값 `net_arch=[64, 64]`, [focused_train.py:173](../src/focused_train.py#L173) |
| 출력 4개는? | 녹색 4개 각각의 Q값(그 녹색을 켜면 앞으로 받을 점수의 예상). 실행할 수 있는 녹색 가운데 Q값이 가장 큰 것을 켠다 | [focused_rl.py:443 `predict`](../src/focused_rl.py#L443) |
| 활성화 함수는 있나? | 있다. 은닉층마다 **ReLU**(음수는 0, 양수는 그대로). 마지막 출력층에는 없다. Q값은 음수도 될 수 있어서 그대로 내보낸다 | SB3 기본값 `activation_fn=nn.ReLU` |
| 크기는? | 가중치 8,580개(64×64+64 + 64×64+64 + 64×4+4). 아주 작은 망이다 | 계산 |
| 왜 MLP인가? | DQN이 보는 것이 **숫자 64개 한 줄**이기 때문이다. SB3의 DQN이 주는 선택지는 3가지다: `MlpPolicy`(숫자 한 줄), `CnnPolicy`(그림·카메라 화면), `MultiInputPolicy`(종류가 다른 입력 여러 개를 묶은 것). 그림도 묶음도 아니므로 MLP가 맞다 | `DQN.policy_aliases` |
| 신경망이 2개인가? | 맞다. **본 망**(매번 배운다)과 **목표망**(5,000단계마다 본 망을 그대로 복사, 정답값 계산에만 쓴다). 정답을 내는 망이 매번 흔들리면 학습이 불안정해서 두 개를 쓴다 | `target_update_interval=5000`, [focused_rl.py:477 `train`](../src/focused_rl.py#L477) |
| on-policy / off-policy는? | DQN은 **off-policy**다. 예전에 겪은 경험을 10만 개까지 저장해 두고, 무작위로 64개씩 꺼내 다시 배운다(경험 저장소). 지금 정책으로 새로 겪은 경험만 쓰는 방식(on-policy, 예: PPO)과 다르다 | `buffer_size=100000`, `batch_size=64` |
| Double DQN인가? | **아니다.** 이름이 비슷한 다른 개선 방법이다(다음 행동은 본 망이 고르고, 그 값은 목표망이 매겨 Q값을 너무 크게 보는 문제를 줄인다). 지금 코드는 기본 DQN에 "실행할 수 있는 녹색만 본다"는 수정만 했다 | [focused_rl.py:470 `allowed_next_values`](../src/focused_rl.py#L470) |

교수님이 회의에서 "double Q network", "on-policy 망과 off-policy 망"이라고 하셨다. 대답은 이렇게 하면 된다.

> 망이 두 개인 것은 맞습니다. 정확한 이름은 본 망(online network)과 목표망(target network)이고, 목표망은 5,000단계마다 본 망을 복사합니다. DQN 자체는 경험을 저장해 다시 쓰는 off-policy 방법입니다. Double DQN은 이와 별개의 개선 방법이고, 저는 아직 쓰지 않았습니다.

#### A-2. "이 문제에 가장 좋은 정책은?" — 실험으로 답한다

미리 알 수는 없다. 그래서 검증 날짜로 비교한다. 선택지는 이렇다.

| 선택지 | 무엇이 다른가 | 이번에 하나? |
|---|---|---|
| 망을 키운다: [128,128], [256,256] | 더 복잡한 관계를 배울 수 있다. 대신 느리고 불안정할 수 있다 | **한다** (교수님 질문) |
| 층을 늘린다: [64,64,64] | 교수님이 말씀하신 "more layers" | **한다** |
| Double DQN | Q값을 너무 크게 보는 문제를 줄인다 | 후보로 보고만 |
| Dueling DQN | "이 상태가 좋은가"와 "이 행동이 더 나은가"를 나눠 계산한다 | 후보로 보고만 |
| PPO·A2C(on-policy) | 정책을 직접 배운다. 경험을 다시 쓰지 않아 시뮬레이션이 더 많이 필요하다 | SUMO가 느려서 불리. 하지 않음 |
| Max-pressure(학습 없는 고전 제어) | 정해진 식으로 대기열을 비교한다 | 선행연구에서 소개. 비교 기준 후보 |

**망 크기 실험 방법**

1. `src/focused_train.py`에 `--net-arch` 옵션을 더한다(예: `--net-arch 128 128` → `policy_kwargs=dict(net_arch=[128, 128])`).
   - 이 파일은 지문에 들어가지 않아 잠근 환경이 그대로다. 모델 파일에 망 크기가 저장되므로 평가 코드도 고치지 않아도 된다.
2. 저장 폴더를 나눈다: `models_v5_net128`, `models_v5_net256`, `models_v5_net64x3`. `training_config.json`에 망 크기와 걸린 시간을 적는다.
3. 후보 3개 × seed 5개 = 15개를 학습한다. 하나에 약 67분이고 5개씩 동시에 돌리므로 3번, 약 3.5시간이다(Colab).
   - 걸린 시간을 꼭 적는다. 교수님 질문이 "비용"이었다.
   - 예상: 지금은 1단계가 약 40ms이고 대부분 SUMO 계산이다. 그래서 망을 키워도 시간은 많이 늘지 않을 것이다. 이 예상을 숫자로 확인한다.
4. 검증 2일 × 무작위 도착으로만 평가한다. DQN 15개 × 2일 = 30번 실행이다.
5. **고르는 규칙을 실행 전에 적어 둔다**: 평균 지연이 지금(64-64)보다 0.6초 이상 줄고(seed 사이 표준편차 0.3초의 2배), 좌회전 지연과 300초 초과 대수가 나빠지지 않으면 바꾼다. 아니면 64-64를 유지한다(작고 빠르다).
6. 시험 날짜는 쓰지 않는다. 시험 결과를 이미 봤으므로 이 실험은 "시험 결과를 본 뒤 추가한 확인"으로 표시한다.
7. 노트북에 새 칸을 만든다. 스위치는 꺼진 채로 두고, 이미 끝난 것은 건너뛰게 한다('모두 실행' 사고 방지).

## 8. 계속 지킬 원칙

- 시험 날짜는 설정을 고르는 데 쓰지 않는다. 이미 본 뒤에 더한 확인은 따로 표시한다.
- 예외는 원인을 재현으로 확인한 그 모양에만 둔다.
- 학습과 비학습을 비교할 때는 보는 정보까지 맞춘다.
- 긴 계산은 Colab에서 한다. 한 비교표는 한곳에서 돌린 결과만 쓴다.
- 고르는 규칙은 실행 전에 적는다.
