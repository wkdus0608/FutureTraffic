# 전체 설계 검토 - 2026-10-05

**결론: 원본 파일을 잘못 복사해 도로망이 깨졌다는 근거는 없다. 그러나 지도·회전교통량·신호를 하나의 교통 환경으로 연결하는 설계는 아직 검증이 끝나지 않았다. 현재 석천사거리 중심 실험은 유용한 예비 실험이며, 원래 12개 교차로 환경의 미반영을 해결한 최종 환경은 아니다.**

이번 검토는 사용자가 요청한 전체 설계에 맞춰 연구계획서·교수 회의록·AI Hub 설명서와 가이드·원본 network XML·19일 회전교통량·후보 경로·기존 생성 경로·현재 focused 코드를 대조했다. 원본과 구현 소스·설정·모델을 바꾸지 않았고, DQN 재학습이나 새 차량 주행 실험은 하지 않았다. 원본 집계·구조 검증·자료 비교와 보고서만 추가했다. 앞선 코드 중심 점검은 `추가_설계검토_20261004.md`에 따로 보존한다.

## 1. 연구 목적과 현재 범위가 달라졌다

연구계획서 2쪽은 **12개 신호교차로가 있는 도로망에서 한 곳만 DQN으로 제어하고, 나머지는 고정신호로 유지**한다고 적었다. 2차 회의에서도 학생이 12개 교차로 중 하나만 제어하겠다고 설명한다. 교수는 교통량·도로망·신호를 결합해 SUMO 환경을 만들고, 자료와 코드가 어떻게 작동하는지 이해하라고 했다. 모든 AI Hub 도시·영상·궤적을 반드시 사용하라는 뜻은 아니며, 주변 11개 교차로를 제외해도 된다는 승인도 원문에서 확인되지 않았다.

현재 focused는 원본 지도 파일을 보유하지만 차량 경로를 석천사거리 주변에서 시작하고 끝낸다. 다른 신호 전, 또는 차로 수가 절반 미만으로 줄어드는 곳 전에서 경로를 끊는다. 이는 제어 범위뿐 아니라 **교통 환경의 범위**도 줄인 것이다.

따라서 다음 효과가 빠지거나 약해진다.

- 상류 신호가 만든 차량 무리와 신호 연동 이득.
- 다른 접근로의 합류와 차로 선택, 주변 교차로를 지나오는 경로 구성.
- 하류 정체가 석천사거리까지 밀려오는 효과와 앞 시간대에서 이어지는 대기열.

클로드가 신호 이어붙이기와 교착을 찾아 고친 것은 필요한 작업이다. 다만 그 성과로 원래 전체 도로망의 문제까지 해결됐다고 설명할 수는 없다. 현재 모델은 보존하고 예비 실험으로 사용하는 것이 타당하다.

근거: 연구계획서 2쪽, `회의 내용/2차회의.txt` 148·152~174·232~237행, `src/focused_scenario.py` 89~123행, PROJECT_PROGRESS 27~29절.

## 2. 교수님과 본 network XML은 제공 원본과 같다

원본 `1200012n.net.xml`과 Sample 및 기존 네 시나리오의 지도 사본은 같은 SHA-256이다. 지도에는 외부 도로 439개, 내부 도로 포함 1,300개, 신호교차로 12곳이 있다. XML 스키마 검사와 도로·차로·내부 연결·신호 인덱스 참조 검사에서 오류는 0이었다. 제공 후보 경로 3,244개도 연결 검사 오류는 0이다.

이는 **우리 복사 과정에서 연결을 지웠다는 가설을 지지하지 않는다.** 하지만 XML이 정상이라는 것이 관측된 모든 회전과 현실의 차로 규제가 정확히 들어 있다는 뜻은 아니다.

확인한 모델의 한계는 다음과 같다.

- 회전량의 도로 ID와 지도 ID가 다른 항목, 직접 연결이 없는 항목, 연결은 있지만 후보 경로가 없는 항목이 각각 존재한다.
- 횡단보도·보행 영역 edge는 0개다. 현재 보행 규칙은 보행자가 실제로 횡단하는 모델의 검증이 아니라 신호 시간 제약이다.
- 외부 차로는 1,332개가 별도 차종 제한 없음, 38개가 전 차량 금지다. 실제 버스전용차로 등의 규제를 충분히 구현했다고 단정할 수 없다.
- 차로 변경을 포함한 실제 주행 가능성은 도로 단위 연결 검사와 별도로 확인해야 한다.
- 지도 헤더의 2022-11-03은 전체 파일 저장 시각이다. E1 도로 자체의 생성일이나 실제 도로 신설일을 뜻하지 않는다.
- 원본에는 유턴 연결 104개가 있지만 문제의 201293 접근 방향 유턴은 없다. XML의 생성 옵션이나 신호 칸 부재만으로 현장 유턴 허용 여부를 판단할 수 없다.

원본 05:00 신호 파일과 지도의 신호 칸 수도 세 곳에서 다르다.

| 교차로 | 지도 신호 칸 | 제공 신호 파일의 칸 |
|---|---:|---:|
| 중앙공원 201306 | 15 | 17 |
| 넘말 201330 | 22 | 23 |
| 송내 cluster_204796_205202 | 24 | 26 |

나머지 아홉 곳은 길이가 같다. 그러나 길이가 같은 것만으로 각 칸이 같은 회전을 제어한다고 검증된 것은 아니다. 특히 여분 두 칸이 빠진 두 회전의 신호라는 해석은 연결별 번호 대응 없이 확정할 수 없다. 전체 도로망에서 제공 신호를 쓰려면 12곳의 회전·차로·신호 칸 대응과 시간축 복원을 확인해야 한다. 현재 기본 시나리오 생성 명령은 지도와 차량 경로를 설정하며, 별도 역사적 신호 파일은 적용하지 않는다. 그 기본 신호는 지도 내장 신호로 구분해야 한다(`src/prepare_sumo_scenario.py` 149~173행).

기본 열은 원본 이동 ID 그대로, 보완 열은 조건부 ID 대응을 적용한 입력과 비교했다. 두 열의 차이를 그대로 보완 효과로 계산해서는 안 된다. 석천사거리 263은 공통 도로쌍 249회와 옛 출구 ID 14회를 합친 값이다. 보완 사본의 465회는 관측 이동 예정 통과 438회와 그 표본에 없는 이동 27회다.

## 5. 기록 없음과 0을 구분하지 않은 시험도 문제가 남았다

19일 `교차로_all`의 네 차종 XML 7,296개를 다시 확인했다. 회전 기록 총합은 13,336,507회, 양수 이동쌍은 162종이다. 파일 지문·원본 헤더·크기·CRC와 기존 전수 수치는 일치했다. 그러나 관계 3,026,772행 중 명시적으로 count=0인 행은 0개였다. 없는 행이 실제 0인지 결측·미측정인지 판별할 측정 상태 정보는 확인하지 못했다.

따라서 19일 중 한 번 나온 이동이 특정 시각에 없으면 0이라고 채우는 것은 별도 가정이다. 현재 진행 기록의 "0대 명시로 초과 0"은 그 가정과 검사 범위를 함께 써야 한다.

기존 900초+0가정 시험에는 추가 문제도 있었다. 입력 양수는 1,628회인데 품질 보고서 분모는 1,614회였다. 이륜차 구간이 다른 차종과 어긋나 겹침 분할·정수화 과정에서 14회가 빠졌다. 보고서 부족 192회와 원본 기준 부족 206회를 구분해야 한다. 또한 19일에 등장한 전체 측정 접근로로 범위를 넓히면 그 표본에 기록이 없는 이동의 예정 통과 112회가 남는다. 이것을 실제 112회 초과라고 확정할 수는 없지만, "전체 초과 0"이라는 주장의 검증 범위가 좁았음을 보여 준다.

이웃 장부 차이만으로 전체 누락 0이 수학적으로 불가능하다고 단정하는 것도 이르다. 기존 흐름 보존 검사의 두 비교는 서로 다른 교차로가 아니라 말단 유턴 후 같은 교차로로 복귀하는 경로였다. 다른 링크의 차이는 남지만 이동 시간, 초기·종료 잔여, 중간 출발·도착, 자료 생성 단계를 반영한 뒤 가능한 수요를 판단해야 한다.

근거: `demand/검토요약.md`, `flow_conservation_review.json`, 기존 `results/design_review_20261004/routesampler/interval_900_zero/`.

## 6. 제공 자료 전체를 현장의 독립 정답으로 취급하면 안 된다

AI Hub 설명서 7쪽에는 실제 수집 대상 교차로 9곳과, 연계를 위해 추가한 비수집 대상 3곳(넘말·복사골·영안)이 구분돼 있다. 그런데 제공 `교차로_all`에는 추가 세 곳의 회전 기록도 합계 3,046,140회 들어 있다. 이 값의 정확한 생성 단계는 이번 자료로 확정하지 못했다. **제공 원본이라는 것과 12곳 전부가 같은 수준의 직접 관측이라는 것은 다르다.**

각 회전량 XML의 count는 한 이동의 통과량이다. 전체 도로망에서 같은 차가 여러 교차로의 장부에 나타날 수 있으므로 1,628회를 고유 차량 1,628대로 넣을 수 없다. 출발지·최종 목적지·실제 도로망 경계 도착 시각도 count만으로 알 수 없다. 회전량에서 경로와 출발 수요를 추정하는 것은 필요하지만 해가 하나로 정해지지 않는다. [SUMO 공식 설명](https://sumo.dlr.de/docs/Demand/Routes_from_Observation_Points.html)도 이 점을 명시한다.

제공 tra/OD는 독립적인 현장 원본 궤적의 정답으로 사용하면 안 된다. 가이드 PDF 72~73쪽은 SUMO 실행 중 차량 상태를 기록해 궤적·회전 테이블·OD를 만드는 절차를 설명한다. 이 가공 결과로 같은 SUMO 지도의 연결이 맞는지 검증하면 기존 모델의 판단을 다시 확인하는 셈일 수 있다. 제공 p/b/t/m의 모든 행이 어느 가공 단계에서 나왔는지는 파일별로 확정되지 않았다.

따라서 현장 사진은 도로 존재·회전 허용을 판단하는 독립 근거로, 신호 원본은 운영 해석의 근거로, 제공 궤적은 가공 모델 내부의 보조 근거로 구분해야 한다.

근거: 데이터설명서 3·6·7쪽, 구축·활용 가이드 PDF 58~61·72~73쪽, `design/전체설계_독립점검.md`.

## 7. 수량을 정확히 넣은 것과 실제 교통흐름 재현은 다르다

focused는 회전 기록 한 건을 교차로를 한 번 통과하는 합성 차량 한 대로 만들고, 15분 안의 도착 시각을 무작위로 다시 정한다. 이동별 수량이 맞는 것은 확인할 수 있지만 실제 차량의 도착 시각·OD·대기열까지 복원한 것은 아니다. 반대로 녹색 중 기록된 통과 시각을 그대로 도착 시각으로 쓰는 것도 신호가 처리한 결과를 입력 수요로 삼는 문제가 있다.

상류 신호와의 주기·시차 일치는 연동 가능성의 강한 근거다. 실제 상류 출발과 이동 시간을 반영하지 않은 균등 도착은 그 효과를 제거할 수 있다. 같은 합성 수요를 모든 정책에 주는 내부 공정성과 현실의 고정신호를 대표하는지는 별개의 검증이다.

운전자 sigma 0·먼 차로 미리 선택·합류 갈래 배분은 안정적인 실행을 만드는 조치지만, 실제 운전자 행동을 검증한 결과는 아니다. 특히 상류 15분 통과량을 하류 같은 15분 통과량으로 나눈 비율은 이동 시간·중간 분기·차종을 반영하지 않으면 차량 출처의 확정 비율이 아니다. 처리량을 맞춰 sigma를 고르는 것으로 실제 지연을 검증하거나 정책 성능에 영향이 없다고 단정할 수도 없다. 연속 실행, 운전자·갈래·경계 조건 민감도와 방향별 대기·완료율을 함께 보고해야 한다.

## 8. 다음 작업의 순서와 끝낼 기준

현재 남은 세 작업(상류 연동, 하루 연속 평가, DQN 재학습)은 필요하다. 다만 이 세 가지는 focused를 개선하는 작업이며 전체 지도-교통량 대응을 자동으로 해결하지 않는다. 원래 목적을 유지한다면 다음 순서가 적절하다.

1. **자료 대응을 먼저 고정한다.** 원본을 보존하고 12개 교차로의 회전 ID·전체 경로·차로 연결·신호 칸 대응과 수집/가공 출처를 표로 정리한다. 유턴 등 미확정은 가정과 보류로 남긴다. 신호 칸이 두 개 더 있다는 이유만으로 빠진 두 회전의 번호라고 확정하지 않는다.
2. **전체 수요를 다시 추정하고 양쪽 오차를 검사한다.** ID·곡선길·후보 경로 보완을 하나의 재현 가능한 생성 과정에 반영한다. 부족뿐 아니라 초과·미관측 이동·차종별 원본 분모 보존을 확인한다. 불일치가 남으면 측정 범위와 원인을 설명하고 수요 민감도를 비교한다.
3. **고정신호로 연속 환경을 먼저 검증한다.** 12개 교차로가 서로 영향을 주는 범위를 유지하고 실제 통과 시간·회전 완료·미진입·잔여·충돌·순간이동·방향별 대기를 확인한다. 축소가 필요하다면 관련 상류 신호·합류·하류 정체를 보존하고 경계 조건에 따른 결과 차이를 검증한다.
4. **그 뒤 수요와 환경을 동결해 DQN을 비교한다.** 날짜를 먼저 나누고 보정에 시험 날짜를 쓰지 않는다. 같은 환경·수요에서 고정·감응식·DQN을 비교하며 평균 개선과 장기 대기 악화를 함께 보고한다.

끝낼 기준은 "모든 가정이 없고 모든 숫자가 0"이 아니다. **자료 출처·대응·경계 조건이 설명되고, 부족과 초과가 함께 측정되며, 남은 가정에 따른 결론 변화가 확인되고, 정책 비교 전에 환경이 고정되는 것**이다. 실제 도로 성능까지 주장하려면 별도 현장 검증이 필요하다.
