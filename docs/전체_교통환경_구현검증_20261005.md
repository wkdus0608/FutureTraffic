# 전체 교통환경 구현·검증 — 2026-10-05

지금은 전체 도로망을 검증하는 단계다. 연구용 DQN 재학습은 보류한다. 환경을 작게 잘라 교통량을 맞추는 대신, 원래 계획의 12개 교차로를 유지하고 204820 한 곳만 제어하는 연구를 준비한다.

## 이번에 구현한 것

1. **원본 장부 보존:** 회전 통과 횟수와 고유 차량 수를 구분한다. 모든 차종의 같은 시간 범위를 읽고, 부족·초과·미해결·미관측을 각각 보고한다. 원본에서 기록이 없는 이동을 자동으로 0대라고 판단하지 않는다.
2. **이동 대응표:** 19일 자료의 162개 이동을 등록했다. 도로 ID 대응과 곡선 우회전 전체 경로를 기록한다. 중앙공원 두 연결은 별도 사본에 추가하고 나머지 11개 신호·외부 도로 형상을 보존했다. 유턴은 원본 분모를 유지한 보류형과 별도의 직진 가정형을 구분한다.
3. **전체 경로 추정:** 도로망의 모델 경계에서 들어와 나가는 후보를 만든다. 유턴으로 연결된 말단을 외부 경계로 보는 옵션을 따로 표시한다. 이 경계와 OD는 실제 차량 여정을 확인한 결과가 아니다.
4. **시간 추정 보완:** 같은 15분의 회전 기록을 같은 15분의 출발량으로 곧바로 쓰지 않는다. 여러 시간창의 회전량과 도로 이동 시간을 함께 사용해 경계 출발량을 추정한다. 녹색 시각에 맞춰 차량을 도착시키지 않는다. 현재 도로 제한속도 기반 추정은 내부 교차로·신호·대기시간을 제외하므로 실제 주행 검사를 반드시 별도로 수행한다.
5. **연속 실행·실제 완료 집계:** 미리 차량을 넣는 구간부터 평가와 배출 구간까지 한 번에 실행한다. 상류 도로를 나간 것만으로 회전 완료라고 세지 않고, 교차로 내부를 거쳐 마지막 도로로 진입한 시각을 사용한다.
6. **전체 신호 검사:** 12개 신호의 각 칸과 실제 차로 연결을 대응시킨다. 제공 신호와 지도의 칸 수가 다른 세 곳, 번호 대응 가정, 황색 보정, 내장 신호로 대체한 구간을 기록한다. 정적 foe 검사와 실제 충돌 검사는 구분한다.
7. **검증 보호:** 원본·입력·실행·출력·검사 코드의 지문을 함께 저장한다. 입력이나 버전이 바뀌면 옛 결과로 새 환경을 승인하지 않는다. 차량 수뿐 아니라 차량 ID까지 비교하고, 집계 분모를 원본 XML에서 독립적으로 다시 계산한다.
8. **지역 지도 가정의 분리:** 세 내부 대기 위치를 옮기는 사본과, 가까운 두 비신호 교차로를 하나로 표현하는 사본을 별도 옵션으로 만든다. 원본과 지역 밖 도로·12개 신호는 보존한다. 보존 검사를 통과한 지도도 실제 주행·현장 대응을 따로 검증하며, 기본 원본을 몰래 대체하지 않는다.

## 추가로 발견한 실제 문제

### 교차로 내부 충돌을 검사하지 않았던 공백

SUMO의 교차로 내부 차량 형상 겹침은 `collision.check-junctions`를 켜야 확인된다. 이 옵션을 켜고 v2와 같은 차량을 다시 실행하니 충돌 4건이 검출됐다. 검사 결과만 알려 주는 `collision.action=warn`을 써서 주행은 바꾸지 않았으며, 차량별 도착·지연 값도 원래 실행과 같았다. [SUMO 공식 안전 설명](https://sumo.dlr.de/docs/Simulation/Safety.html#collisions)

4건은 정지한 버스의 몸체와 다른 연결을 지나는 차량의 작은 형상 겹침이다. 201305 유턴 2건, 201330 좌회전 1건, 비신호 203019 좌회전 1건이다. 버스는 내부 양보 지점에서 정상적으로 정지했다. 같은 차로의 앞뒤 간격 위반이나 황색·적색 전환 시점의 잔여 차량 충돌이 아니었다. 이것을 실제 도로에서 사고가 났다는 뜻으로 해석하지 않는다. 내부 대기 위치와 차량 몸체 표현을 검증해야 한다.

**대기 위치 사본 결과:** 세 지점을 기존 경로를 따라 1m 옮겼다. 외부 차로, 55개 전체 내부 경로와 총 길이, 교차로 외곽선, 연결·양보 규칙, 12개 신호는 그대로다. netconvert가 함께 바꾼 요청 행 8개와 다른 내부 양보 규칙 2개는 원래대로 복원했다. 이 보존형을 같은 차량·출발·신호로 실행하니 기존 4건은 사라졌지만, 변경하지 않은 비신호 교차로 **201286에서 버스 두 대의 충돌 1건**이 나타났다. 이곳은 기존 세 곳의 내부 대기 위치와 같은 원인으로 아직 확정하지 않았다. 앞선 정체가 달라지면 다른 잠재 문제가 드러날 수 있어, 세 곳만 고친 결과를 전체 안전 통과로 보고하지 않는다.

기존 급제동 1건은 별도의 단일 트럭 시험에서 황색→적색 전환과 내부 통과 동작이 원인임을 확인했다. 해당 신호만 계속 녹색으로 두면 급제동이 사라졌다. 이것은 원인 확인용 시험이며 실제 신호를 상시 녹색으로 고친다는 뜻이 아니다. 전체 지도 사본에서 급제동이 0인 것은 다른 차량의 타이밍도 바뀐 결과이므로 원인 제거의 증거로 대신 사용하지 않는다.

또한 내장 cluster 신호의 반대편 좌회전 두 개가 정적 foe 검사에 걸렸다. 두 차 동시 진입의 네 가지 작은 재현에서는 충돌이 없었으므로, **정적 검사 실패를 실제 충돌과 동일시하지 않는다.** 제공 신호 26칸과 지도 24칸의 대응도 아직 확정되지 않았다.

### 숫자 일치만으로 환경을 승인할 수 없음

실제 도로망 진입량·출발지와 목적지·초기 대기열은 회전 합계만으로 하나로 정해지지 않는다. 처음 같은 시간창에 배정한 예정 통과 12,724회 중 2,432회(19.1%)는 실제로 다음 시간창 이후에 완료됐다. 이동 시간을 넣은 새 추정도 신호 지연과 대기열을 정확히 복원하지 못했다. 운전자 시야만 늘려서는 전체망의 미진입·미완료도 해결되지 않았다.

따라서 현재 상태를 “미반영 0, 교통환경 완성”이라고 보고하지 않는다. 연결 대응, 경계 OD 가정, 시간 추정, 실제 도로 처리 능력과 신호 의미를 각각 검증한다.

### 새로 확인한 가까운 비신호 교차로의 상호 교착

시야 3,000m 시험에서 버스 한 대는 34분 동안 `:204922_1_0`에 멈췄다. 두 비신호 교차로 **204922·605257**의 차량들이 서로 막고 있었으며, 두 곳을 잇는 외부 도로 `477771616_01/02`는 각각 **0.29m**다. SUMO도 가까운 별도 교차로 사이에서 긴 차량의 상호 차단이 생길 수 있다고 설명한다. [공식 교차로 결합 설명](https://sumo.dlr.de/docs/Networks/PlainXML.html#joining-nodes)

전체를 재작성하지 않고 이 지역만 합친 사본을 만들었다. 삭제되는 두 연결 구간은 162개 원본 회전 이동의 도로 번호 및 등록된 전체 대응 경로에 쓰이지 않는다. 지역 밖 모든 요소·바깥쪽 차로 끝점·12개 신호를 보존했고, 원본에서 그 연결을 통해 가능했던 외부 도로 이동도 유지했다. 신호 교차로 12곳을 제거하거나 연구 범위를 줄인 작업이 아니다.

| 같은 7,044대·운전자·출발·신호·seed의 비교 | 미진입 | 실행 종료 시 잔여 | 충돌 |
|---|---:|---:|---:|
| 기존 시야 3,000m 사본 | 365 | 641 | 8 |
| 두 비신호 교차로만 결합, 기존 15분 배출 | 0 | 30 | 6 |
| 위와 같은 사본, 배출만 90분으로 연장 | 0 | 0 | 6 |

앞서 막혔던 네 차량도 모두 도착했다. **교착을 줄이는 모델 수정 근거는 있지만 충돌이 남아 학습 승인 조건은 충족하지 않는다.** 결합하면 그 지역의 형상과 통행 우선순위가 다시 계산되므로, 실제 현장 우선순위의 복원으로 확정하지 않는다. 계산 간격을 1초에서 0.2초로 줄인 민감도 시험도 충돌 7건·미진입 341대·잔여 496대였다. 이 시험은 난수 소비·차량 반응 시점도 바뀌므로 동일 궤적 비교가 아니며, 계산 간격만 바꾸면 안전해진다고 결론 내리지 않는다.

두 지도 가정을 통합한 도구로 경로를 새로 생성한 5,107대도 모두 도착했으나 충돌 1건, 수집 지점 회전량 절대오차 15.0%가 남았다. 이는 기존 7,044대와 수요가 달라 별도의 통합 실행 검사이며, 개선 효과의 단일 조건 비교에 섞지 않는다.

## 환경 확정 전에 남은 일

1. 남은 충돌을 회전·차로·차종별로 확인한다. 이미 확인한 세 대기 위치와 같은 원인으로 자동 분류하지 않는다. 구조 보존 검사와 실제 안전 검사를 둘 다 통과해야 한다.
2. 경계 출발량과 대기시간을 함께 설명하는 수요 모델이 시간대별 실제 통과량과 미진입·미완료 검사를 통과해야 한다. 모든 관측량을 동시에 맞출 수 없다는 결론은 후보와 시간 모델의 한계를 확인하지 않고 내리지 않는다.
3. 유턴 기록의 의미, 세 곳의 신호 칸 대응, 추가 지점 자료 생성 과정을 확인해야 한다. 확인 전에는 명시적인 가정형으로 유지한다.
4. 보행 시간 제약과 보행자가 실제로 횡단하는 환경을 구분해야 한다. 기존 지도에는 보행 횡단 edge가 없으며, 현재 전체망 도구는 차량 환경 진단이다.
5. 환경 확정 뒤에는 기존 학습 코드의 갈래 감지 누락, 실행 불가능 행동의 미래 가치, 기본 날짜 분할, 정책 간 제약과 캐시 버전 문제도 새 전체망에 연결하며 수정해야 한다(진행 기록 30절). 현재 새 도구는 환경 진단용이며 기존 focused 학습 명령이 자동으로 새 환경을 쓰게 바꾼 상태가 아니다.
6. 그 뒤 환경과 날짜 분할을 동결하고 같은 수요·운전자·보행 및 신호 제약에서 고정·감응식·DQN을 비교한다. 평균 지연뿐 아니라 방향별 장기 대기, 도로 진입 전 대기, 미완료도 포함한다.

최종 네트워크 관련 검사 **88개 통과**(10.193초). 실제 주행 실패 결과까지 보존하고 모든 사본의 `learning_ready=false`를 유지한다. 1시간 진단 통과가 19일 전체 또는 실제 교통환경의 검증을 뜻하지 않는다.
