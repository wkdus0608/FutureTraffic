# PLATOON0 실행 안내 (0단계: 동쪽 무리 도착 경기장의 여지 재기)

- **무엇:** 지금 단독 교차로 경기장(ARENA3)은 차가 15분 안에서 무작위로 와서, 앞으로 올 차를 알아도 쓸모가 없었다(111·238절).
  같은 차의 동쪽 출발 시각만 이웃 신호(204822)의 실제 녹색에 맞춘 경기장에서, 계획기가 앞으로 올 차를 알거나 예측하면
  M4보다 얼마나 줄일 수 있는지 잰다. 학습은 없다. 기준은 `results/explore/platoon0_20261031/사전등록.md`(실행 전 고정).
- **세계:** R = ARENA3 그대로(무작위), P = 동쪽 차만 204822 녹색에 맞춤(기존 무리 도착 규칙, 차마다 고정 난수).
- **제어(모두 같은 계획기·M4 가중):** M4(기준) / P1M4(달리는 차 + 최근 진입 비율) / TM4(+ 204822 시간표로 동쪽 예측) /
  OM4(앞으로 올 차를 정확히 앎).
- **규모:** ARENA3 평가 84상황 × (P 세계 4제어 + R 세계 2제어) = 504판. Colab CPU 8개 런타임 하나로 약 4~5시간(맥 작은 실행에서 판당 2~3분).

## 순서
1. Drive `FutureTraffic/`에 `FutureTraffic_PLATOON0.zip`과 `PLATOON0_Colab.ipynb`가 있는지 확인한다.
   ARENA3 심판 기준선(`arena3/referee/baseline`)은 읽기만 한다.
2. 노트북을 열고 런타임 유형을 **CPU + 높은 RAM(CPU 8개)** 으로 고른 뒤 **모두 실행**.
3. 칸 순서: 묶음 검증 → 패키지 확인 → 시험(SUMO 없음) → 작은 실행(차량 파일 84개 점검 + 6판, 약 10~15분)
   → 본 실행(백그라운드) → 판정.
4. 끊기면 다시 **모두 실행**한다. 끝난 판(`cache.json`이 있는 폴더)은 건너뛴다. 작은 실행이 통과했으면 다시 하지 않는다.

## 판정(사전 등록)
- 주: P 세계 OM4 − M4 날짜 평균 ≥ 2.0초이고 t95 하한 > 0 → **여지 있음**, < 1.0초 → **없음**, 그 밖 **불분명**.
- 원인: 날짜별 [P 세계 몫 − R 세계 몫]의 t95 하한 > 0 → 무리 도착 때문에 생긴 몫.
- 시간표 몫: TM4 몫 ÷ OM4 몫 ≥ 0.5 → 이웃 시간표로 절반 넘게 잡힌다.
- 재현 점검: R 세계 M4 84판이 ARENA3 기준선 M4와 차량당 지연·실행 녹색까지 같아야 결과를 읽는다.
