# WEIGHT1 밤샘 묶음 실행 안내 (2026-10-27)

이 문서는 실행 전에 고정한 계획이다. 구현과 가짜 에피소드 검사까지 끝났고, 실제 SUMO·학습은 사용자가 Colab에서 실행한다. 맥에서는 실행하지 않는다.

## 왜 하는가

WEIGHT1 긴 학습(3모델×417에피소드)은 P0보다 0.88초 짧았지만 고정 M4와는 0.06초 차이로 구분되지 않았다(186절). 진행 기록 187절에서 세 방법(탐색 제어·고정 M4·RL)이 P0 대비 약 1초에서 만나는 것을 보고, WEIGHT2를 바로 돌리기 전에 "M4 위로 더 나아질 여지가 있는가"를 싸게 확인하기로 했다. 같은 밤에 M4에서 출발하는 학습 하나를 함께 시험한다.

## 무엇을 돌리나

| 이름 | 내용 | 실행 수 | 고정한 판정 규칙 |
|---|---|---:|---|
| N1 | 탐색 제어를 시험했던 6쌍(08-22 13:00·09-06 18:00·09-07 13:00 × 난수 42·43)에서 P0와 고정 M4를 다시 돌려, 같은 쌍에서 탐색 이득과 M4 이득을 비교 | 12 | (탐색 이득 − M4 이득)의 6쌍 평균이 0.5초 이상이면 "M4 위의 여지 단서", 아니면 "여지 근거를 못 얻음" |
| N2 | M4(동·남 좌회전 가중치 2.0) 주변의 고정 가중치 (2.5,2.5)·(3,3)·(4,4)·(3,2)·(2,3)를 개발 16조건에서 비교 | 80 | 개발 평균이 M4보다 0.3초 이상 짧으면 "확인 평가를 해 볼 만한 단서" |
| N3 | M4에서 출발하는 듀얼링 DQN. 학습 seed 42·43·44, 각 139에피소드, 42·139에피소드 모델을 개발 16조건에서 평가 | 학습 417에피소드 + 평가 96 | 139에피소드 평균이 M4보다 0.3초 이상 짧고 3개 중 2개 이상이 M4보다 짧으면 "M4 초과 단서", ±0.3초 안이면 "M4 수준", 0.3초 넘게 길면 "M4보다 나쁨" |

재현 확인으로 개발 조건 2곳에서 P0·M4를 다시 돌려 이전 기준값과 소수점까지 같은지 본다(4회). 같지 않으면 요약에 "재현 불일치"가 표시되고 N1·N2의 해석 신뢰가 낮아진다.

## N3 학습기가 기존과 다른 점

환경·110칸 관측·5개 모드·보상·에피소드는 WEIGHT1과 같다. 학습기만 다르다.

- `Q(s,m) = V(s) + A(s,m) − A(s,b(s))`. `b(s)`는 M4와 같은 첫 신호를 내는 가장 작은 유효 모드이고 V·A 출력층은 0으로 시작한다. 그래서 학습 전 탐욕 정책이 정확히 M4다.
- 모드가 갈리는 판단은 전체의 약 2%뿐이라, 미니배치의 25%를 그런 판단에서 뽑는다.
- 탐험은 유효 모드 중 무작위, 0.5에서 0.2로 줄이고 그 뒤 0.2 유지(기존은 1.0에서 0.05).
- 학습 에피소드에 설명 안 되는 충돌이 있으면 그 에피소드만 버리고 기록한다(최대 5개). 다른 품질 실패는 그대로 멈춘다.
- 학습 날짜 11일, 학습 시나리오 순서, SUMO 난수(seed+에피소드 번호)는 기존 WEIGHT1 모델 42·43·44와 같다.

## 실행 방법

1. 새 ZIP `FutureTraffic_NIGHT.zip`을 Drive의 `MyDrive/FutureTraffic`에 둔다(기존 결과 폴더는 건드리지 않는다).
2. 새 노트북 `Night_Colab.ipynb`를 Colab에서 열고 런타임 → 모두 실행.
3. 처음 약 10분(검사·등록·스모크 테스트: 실제 SUMO 에피소드 3개)을 지켜보고 `SMOKE PASSED`를 확인한 뒤 주무신다. 스모크가 실패하면 밤샘 실행은 시작되지 않는다.
4. 학습 3개와 점검이 동시에 돌고, 끝나면 학습 모델을 자동 평가하고 요약한다. 결과는 `explore_night_v1/`(요약은 `summary.md`).

CPU가 4개 이상인 런타임을 권장한다. 4개 기준 예상은 벽시계 약 6시간, 작업시간 약 21시간이다.

## 안전장치

- 코드·설정·자료·패키지 지문을 `experiment.json`에 고정한다. 결과가 있는데 코드가 다르면 이어 하지 않는다.
- 계산 장부는 이전 실험(63.54시간)에 이어서 합산한다. 이번 밤샘 상한 30작업시간, 전체 96시간 한도 직전에 스스로 멈춘다. 벽시계 12시간 뒤에도 새 작업을 시작하지 않는다.
- 연결이 끊기면 다시 모두 실행하면 된다. 학습은 마지막으로 끝난 에피소드부터, 평가는 끝난 실행을 건너뛰고 이어 간다.
- 기존 `explore_weight_resume_v1`은 읽기만 한다(개발 기준 실행 32개와 장부).

## 해석 범위

모두 반복 사용한 날짜의 추가 개발 평가다. 새 날짜·실제 도로 일반화나 확인 평가가 아니다. 개발 평가에서 고른 것은 확인 전에 성능 주장에 쓰지 않는다. 결과를 보고 판정 규칙·조건·seed를 바꾸지 않는다. 학습 seed 3개의 한계가 있다.
