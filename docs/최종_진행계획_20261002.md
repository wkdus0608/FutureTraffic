59건 미반영보다 먼저 고쳐야 할 문제가 네 가지 있다. 모두 지금까지의 고정신호·DQN 결과에 영향을 준다.

|---|---|---|
| 생성 경로가 관측된 방향을 약 2배 지나감 | 관측 1,628건을 생성 경로가 3,178번 지남. 204820은 관측 263 → 438(+67%). 예: `477706392_02→477706883_02` 관측 3, 경로 51. 품질 보고서는 "초과 0" | 차량 수가 2배라는 뜻은 아니다. 경로에 예정된 통과 횟수 기준이며, 실제 통과 시각 기준 검증은 4단계에서 한다 |

### 2.1 수요 생성 시험 (scratchpad, 15분 샘플, 지도 그대로, 경로 기준)

| 방식 | 차량 | 부족 | 관측 이동 초과 | 관측 교차로의 미관측 이동 통과 | 204820 관측/경로 |

| 현재 (1분 구간) | 1,305 | 59 | 1,609 | — | 263 / 438 |

### 2.2 신호 자료

- **열 순서:** 길이가 같은 9개 교차로에서 지도의 우회전 연결 위치와 신호 자료의 "항상 g" 열이 모두 일치한다. 열 순서가 linkIndex 순서라는 강한 근거다. 204820은 접근로별 구조(우회전 1 + 같은 패턴 직진 5 + 좌회전 1 + 유턴 1)도 지도와 맞는다. 다른 교차로의 직진·좌회전 열 대응은 교차로별로 따로 확인해야 한다.
- **시각:** 공식 설명은 `aringstarttime` = 신호시작시간이다. 이 정의와 각 행의 상태를 그대로 짝지으면 황색이 17~66초가 되어 비현실적이다. XML 지속시간은 "각 행의 상태가 그 시각에 끝난다"로 읽어야 맞는다.
  - 시각 또는 상태 표기가 한 행 어긋나 있다는 뜻이다.
  - 다만 어느 쪽으로 읽어도 녹색별 시간은 같다. 황색 상태가 직전 녹색을 알려주기 때문이다.
  - 204820 05:00의 녹색별 시간은 길주로 좌회전 66초, 석천로 직진 17초, 석천로 좌회전 46초, 길주로 직진 16초다.
- **현시–이동 대응:** 9곳 중 5곳에서 긴 녹색이 교통량 적은 좌회전에 간다. 그 교차로들만 녹색 상태 표기가 한 현시씩 밀렸을 가능성(예: 선행/후행 좌회전 순서 차이)이 있다. 그러나 **교통량과 더 잘 맞는다는 이유만으로 옮기지 않는다.** 검증 기준은 4단계 3단계에 적었다.
- **행동 수:** XML을 그대로 SUMO-RL에 넣으면 반복된 녹색 때문에 행동이 22개가 된다. 고정신호 재생용 프로그램과 DQN용 4개 녹색 틀을 따로 만든다.

## 3. 기본 결정 (가정은 가정으로 표시)

1. **수요:** 15분 합계 + 최적화.
   - 출발 시각 분포는 분 단위 관측 총량에서 만든다(`--depart-distribution`).
   - 0건 명시 기준: 19일 동안 한 번이라도 기록된 이동은 "측정되는 이동"으로 보고, 해당 15분에 없으면 0으로 명시한다.
   - 한 번도 기록되지 않은 이동은 측정 여부를 알 수 없으므로 제한하지 않는다. 대신 통과량을 따로 보고하고, 0 명시를 민감도로 비교한다.
   - 연계 교차로 3곳은 처음에 0 명시를 하지 않는다.
2. **이동 처리표:**
   - ID 대응: 3종류
   - 곡선도로 대응: 6개(37건)
   - 중앙공원 연결 복원: 2개(5건)
   - **유턴 → 직진: 가정으로 표시하고 기본 시나리오에 적용, "제외" 시나리오를 함께 보고**
3. **신호 기준선:** 3단계 검증을 통과하면 AI Hub 신호 자료, 아니면 지도 내장 신호. 내장 신호를 쓰면 보고서에 명시한다.
4. **DQN 제약:**
   - 행동은 기준 신호의 서로 다른 녹색 4개, 황색은 기준 신호와 같게 한다.
   - 최대 녹색은 기준 신호의 최대 이상이거나 강제하지 않는다.
   - **최소 녹색은 가정이다.** 관측 최솟값은 운영상 최소 허용시간이 아니다. 현재 5초와 근거를 적은 값(예: 관측 최솟값 15초)을 민감도로 비교한다.
5. **실험 시간대:** 하루 대표 시간대(오전 첨두·낮·오후 첨두·심야). 전체 96개는 계산량을 보고 확대한다.

### 1단계 — 수요 생성 (15분 샘플, 지도 그대로)
- `prepare_sumo_scenario.py`에 다음 옵션을 추가한다. 기존 방식은 `--legacy` 비교 모드로 남긴다.
  - 15분 합계와 최적화
  - 출발 분포
  - 진입 속성
  - 처리표(`config/movement_resolution.csv`) 적용
  - 0건 명시
- 처리표에는 원본 쌍, 처리 종류, 바꾼 쌍, 근거, 가정 여부, 상태를 적는다. 분모 1,628건은 유지한다.
- 곡선도로 대응은 "분기 도로 → 곡선 도로" 쌍으로 한다. 이 쌍은 그 회전만 쓰는 길이라 중복 집계가 없다.
- 후보 경로를 보강한다. 모든 관측·대응 이동마다 차종별로 통행 가능한 경계→경계 경로를 여러 개 만든다. 19일 전체에서 기본 후보에 없는 이동 10종류도 포함한다.
- 19일 회전량으로 "측정되는 이동" 목록을 만든다(Drive 읽기 전용).
- 실행할 때마다 지도·처리표 버전, 차량 수, 반영·보류·부족·초과 수량을 출력한다(103/59 혼동 방지).
- **통과 기준(경로 기준):**
  - 204820 부족·초과 0
  - 관측 이동 초과 0
  - 측정되는 이동의 0 명시 위반 0
  - 부족은 처리표상 보류 외 0이 목표이고, 남으면 원인별로 목록화

### 3단계 — 신호 기준선
