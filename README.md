# 석천사거리 신호 비교 실험 (AI Hub 교통량 + SUMO + DQN)

**질문: 교통 수요와 운전자 조건을 고정하고 신호제어만 바꾸면 무엇이 달라지는가?**

AI Hub 71572의 부천 교통량으로 석천사거리(신호 번호 `204820`)를 SUMO 가상 도로에 만들고, 같은 차량·같은 운전자 조건에서 신호만 바꿔 비교한다.

| 비교하는 신호 | 뜻 |
|---|---|
| 고정신호 | AI Hub에 기록된 실제 운영 신호를 그대로 재생 |
| 감응식 | 실제 신호의 녹색 4개를 차량 감지에 따라 늘이고 줄임(참고 기준) |
| DQN | 강화학습이 5초마다 녹색 4개 중 하나를 고름(보행 시간 등 운영 규칙은 지킴) |
| 단순 제어(참고) | 학습 없이 5초마다 기다리는 차가 가장 많은 녹색을 켬. DQN과 규칙은 같지만, 차마다 갈 방향(직진·좌회전)을 알아 정보가 더 많다 |

결론의 범위는 "AI Hub 교통량으로 만든 SUMO 가상 도로에서의 비교"다. 실제 도로 성능을 주장하지 않는다.

## DQN 구조 (2026-10-08 교수님 질문)

| 질문 | 답 |
|---|---|
| 신경망 모양 | 입력 64 → 은닉층 64 → 은닉층 64 → 출력 4(MLP). 은닉층 2개, 층마다 64칸. 가중치 8,580개. Stable-Baselines3 2.9.0 기본값(`net_arch=[64, 64]`) |
| 출력 4개 | 녹색 4개 각각의 Q값(켜면 앞으로 받을 점수의 예상). 규칙상 그대로 켜질 수 있는 녹색 중 가장 큰 것을 켠다 |
| 활성화 함수 | 은닉층마다 ReLU. 출력층에는 없다(Q값은 음수도 되므로 그대로 내보냄) |
| 왜 MLP | 관측이 숫자 64개 한 줄이라서. SB3 DQN의 선택지는 `MlpPolicy`(숫자 한 줄)·`CnnPolicy`(그림)·`MultiInputPolicy`(여러 종류 입력 묶음) 셋이다 |
| 신경망 2개 | 본 망(매번 배움)과 목표망(5,000단계마다 본 망을 복사, 정답값 계산용). 정답을 내는 망이 덜 흔들려 학습이 안정된다 |
| off-policy | DQN은 off-policy다. 지난 경험을 10만 개까지 저장해 두고 64개씩 꺼내 다시 배운다 |
| Double DQN인가 | 아니다. 기본 DQN에 "실행할 수 있는 녹색만 본다"는 수정만 했다(`src/focused_rl.py`의 `HoldAwareDQN`). Double DQN·Dueling DQN은 따로 있는 개선 방법이다 |
| 가장 좋은 구조 | 미리 알 수 없어 검증 날짜에서 비교한다: 64-64(지금)·128-128·256-256·64-64-64, 각 seed 5개, 걸린 시간도 기록. 계획은 [앞으로의 계획](docs/앞으로의_계획_20261009.md) |
| 망을 키우면 느려지나 | 거의 아니다(10-10 측정). 100,000단계 학습 예상 시간은 64-64 66.5분, 512-512 66.8분, 1024-1024 68.6분이다. 시간의 99% 이상이 SUMO 계산이라서다. GPU는 판단마다 데이터를 주고받느라 오히려 느리다(68.7~70.0분) |
| MLP가 최적인가(10-15 진단) | 종류는 맞다(선형보다 낫다, 검증 R² 0.917 → 0.938). 크기도 64-64면 충분하다(32-32~256-256-256 같음). 다만 학습된 DQN의 Q값은 '판단 20번(100초) 앞까지'만 담는다(목표망 교체 약 20번). 개선할 곳은 학습 설정이다 — [MLP 판단](docs/MLP_판단_20261015.md) |

```bash

```

- 첫째: 자동 검사(약 2분). 둘째: 실제 운영 신호로 하루를 돌려 가상 도로를 점검(하루 약 1~2분). 셋째: 원본에서 `data/derived` 표를 다시 만든다.
- 시험 날짜(08-10, 10-28, 08-21, 09-10)는 설정을 고르는 데 쓰지 않는다.

평가와 학습(긴 실행은 Colab에서):

```bash
.venv/bin/python src/focused_eval.py run --dates 20220928 20220813 --policies fixed actuated --workers 4
```

```bash
.venv/bin/python src/focused_eval.py report --dates 20220928 20220813
```

```bash
.venv/bin/python src/focused_train.py --seed 42 --timesteps 100000 --resume
```

- 평가는 하루를 끊지 않고 돌린다(하루 한 정책 약 4~5분). 결과는 `results/focused_204820/eval/<평가 지문>/`에 쌓이고, 코드·설정·자료가 바뀌면 지문이 바뀌어 새로 계산한다.
- 학습은 모델 하나에 이 맥에서 약 70분(100,000단계)이다. `--resume`이면 끊긴 곳에서 이어서 한다. DQN 평가는 `--policies dqn --models results/focused_204820/models/seed_42`처럼 학습 폴더를 준다.
- DQN 결과는 모델 파일 지문별 폴더에 쌓인다(모델을 바꾸면 새로 평가). 보고에 DQN을 넣을 때도 `--models`로 비교할 모델을 준다. 날짜 × 정책(DQN은 모델마다) 가운데 하나라도 빠지면 보고서를 만들지 않는다.

## SUMO 화면으로 보기 (이 맥에서)

```bash
.venv/bin/python src/focused_view.py --date 20220811 --start 0800
```

- 실험과 같은 차량·신호로 장면을 만들어 SUMO 창을 연다. 화면 시계는 실제 시각이고, 시작 10여 분 전부터 차를 넣어 대기열이 있는 상태로 시작 시각에서 멈춘다. ▶(Run)을 누르면 이어진다.
- `--start 1800`처럼 시각을 바꾸고, `--policy actuated`로 감응식을 본다. DQN 장면은 학습한 모델이 생기면 추가한다.
- 창이 열리지 않으면 XQuartz를 한 번 실행한 뒤 다시 시도한다.

## Colab에서 돌리기

1. 맥에서 `.venv/bin/python src/focused_package.py` → `results/colab/FutureTraffic_focused.zip`(약 25MB)
